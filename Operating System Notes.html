1. Introduction to Operating Systems
ENGLISH
An Operating System (OS) is software that manages hardware and gives programs a safe, easy way to use it. It sits between the user/apps and the hardware.
  • Functions: process management, memory management, file management, I/O/device management, security and protection, user interface.
  • Types: Batch (jobs run in groups, no interaction), Multiprogramming (several jobs in memory, CPU never idle), Time-sharing/multitasking (CPU switches fast so many users feel parallel), Real-time (hard = deadline must be met, e.g. airbag; soft = deadline preferred, e.g. video), Distributed, Embedded, Multiprocessor.
  • Goals: convenience, efficiency, and resource sharing. Examples: Windows, Linux, macOS, Android.
HINGLISH
Operating System (OS) wo software hai jo hardware ko manage karta hai aur programs ko use karne ka safe aur easy tareeka deta hai. Ye user/apps aur hardware ke beech baitha hota hai.
  • Functions: process management, memory management, file management, I/O/device management, security aur protection, user interface.
  • Types: Batch (jobs group me chalte hain, interaction nahi), Multiprogramming (kai jobs memory me, CPU idle nahi), Time-sharing/multitasking (CPU tezi se switch karta hai, isliye sab ko parallel lagta hai), Real-time (hard = deadline zaroor, jaise airbag; soft = deadline behtar, jaise video), Distributed, Embedded, Multiprocessor.
  • Goals: convenience, efficiency aur resource sharing. Examples: Windows, Linux, macOS, Android.
2. OS Structure: Kernel, System Calls & Modes
ENGLISH
  • Kernel: the core of the OS that always runs in memory. Shell is the program through which the user talks to the kernel.
  • Dual mode: user mode (apps, restricted) and kernel mode (OS, full access). A mode bit tells which; this protects the system.
  • System call: the way a user program asks the kernel for a service (open, read, fork, exec, write). It switches to kernel mode via a trap.
  • Interrupt: a signal (from hardware) that makes the CPU pause and run an interrupt handler. Trap/exception comes from software (divide by zero, system call).
  • Kernel designs: Monolithic (everything in kernel; fast, one bug can crash all; Linux), Microkernel (only basics in kernel, rest in user space; safer, slower), Layered, Hybrid (Windows, macOS).
  • Booting: power on → BIOS/UEFI → bootloader → kernel loads → init/system processes start.
HINGLISH
  • Kernel: OS ka core jo hamesha memory me rehta hai. Shell wo program hai jisse user kernel se baat karta hai.
  • Dual mode: user mode (apps, restricted) aur kernel mode (OS, full access). Mode bit batata hai kaunsa mode hai; isse system protected rehta hai.
  • System call: user program kernel se service maangne ka tareeka (open, read, fork, exec, write). Trap se kernel mode me switch hota hai.
  • Interrupt: hardware ka signal jo CPU ko rokkar interrupt handler chalata hai. Trap/exception software se aata hai (divide by zero, system call).
  • Kernel designs: Monolithic (sab kernel me; fast, ek bug se sab crash; Linux), Microkernel (kernel me sirf basics, baaki user space me; safe, slow), Layered, Hybrid (Windows, macOS).
  • Booting: power on → BIOS/UEFI → bootloader → kernel load → init/system processes start.
3. Processes: States, PCB & Context Switch
ENGLISH
A program is a file on disk (passive); a process is a program in execution (active). A process has code (text), data, heap, and stack.
  • States: New → Ready (waiting for CPU) → Running → Waiting/Blocked (for I/O) → back to Ready; finally Terminated. Running → Ready happens on a preemption (time over).
  • PCB (Process Control Block): the OS record of a process: PID, state, program counter, CPU registers, scheduling info, memory info, open files.
  • Context switch: saving the running process’s PCB and loading another’s. It is pure overhead (no useful work).
  • fork() creates a child (copy of parent; returns 0 in child, child PID in parent); exec() replaces the process image with a new program; wait() parent waits for child.
  • Zombie: child finished but parent has not read its exit status. Orphan: parent died first; init adopts the child.
  • IPC (inter-process communication): shared memory (fast) and message passing; pipes, sockets, signals.
HINGLISH
Program disk par file hai (passive); process wo program hai jo chal raha hai (active). Process me code (text), data, heap aur stack hota hai.
  • States: New → Ready (CPU ka wait) → Running → Waiting/Blocked (I/O ka wait) → wapas Ready; aakhir me Terminated. Running → Ready tab hota hai jab time khatam (preemption).
  • PCB (Process Control Block): process ka OS record: PID, state, program counter, CPU registers, scheduling info, memory info, open files.
  • Context switch: chalte process ka PCB save karke dusre ka load karna. Ye sirf overhead hai (koi useful kaam nahi).
  • fork() child banata hai (parent ki copy; child me 0 return, parent me child ka PID); exec() process ki jagah naya program load; wait() parent child ka wait karta hai.
  • Zombie: child khatam par parent ne uska exit status nahi padha. Orphan: parent pehle mar gaya; init child ko adopt karta hai.
  • IPC: shared memory (fast) aur message passing; pipes, sockets, signals.
Example: fork() called once makes 2 processes; called n times makes 2n processes in total.
4. Threads & Multithreading
ENGLISH
A thread is the smallest unit of CPU execution inside a process. Threads of one process share code, data, heap and open files, but each has its own stack, registers and program counter.
  • Benefits: responsiveness, resource sharing, cheaper than processes (creation and context switch are faster), use of multiple cores.
  • Process vs thread: process = heavy, isolated memory; thread = light, shares memory (so needs synchronization).
  • User-level threads (managed by a library; fast, but one blocking call blocks all) vs kernel-level threads (managed by OS; true parallelism).
  • Models: many-to-one, one-to-one (Linux, Windows), many-to-many.
  • Concurrency = tasks interleaved (one core); parallelism = tasks truly at the same time (many cores).
HINGLISH
Thread process ke andar CPU execution ki sabse chhoti unit hai. Ek process ke threads code, data, heap aur open files share karte hain, par har thread ka apna stack, registers aur program counter hota hai.
  • Fayde: responsiveness, resource sharing, process se sasta (creation aur context switch fast), multiple cores ka use.
  • Process vs thread: process = heavy, memory alag; thread = light, memory share (isliye synchronization chahiye).
  • User-level threads (library manage karti hai; fast, par ek blocking call sab ko block karti hai) vs kernel-level threads (OS manage karta hai; sachcha parallelism).
  • Models: many-to-one, one-to-one (Linux, Windows), many-to-many.
  • Concurrency = tasks interleave (ek core); parallelism = tasks sach me ek saath (kai cores).
5. CPU Scheduling Algorithms
ENGLISH
The scheduler picks which ready process gets the CPU. Preemptive = OS can take the CPU away; non-preemptive = process keeps it until it finishes or blocks.
  • Terms: Arrival Time (AT), Burst Time (BT), Completion Time (CT), Turnaround Time TAT = CT − AT, Waiting Time WT = TAT − BT, Response Time = first CPU − AT.
  • FCFS: first come first served; simple; convoy effect (short jobs stuck behind a long one).
  • SJF: shortest burst first; gives minimum average waiting time; needs burst estimate; can starve long jobs. Preemptive version = SRTF.
  • Priority: highest priority first; starvation fixed by aging.
  • Round Robin: each process gets a time quantum, then goes to the back of the queue; good for time-sharing. Too large quantum → FCFS; too small → too many context switches.
  • Multilevel Queue / MLFQ: several queues with different policies; MLFQ lets processes move between queues.
HINGLISH
Scheduler decide karta hai kaunse ready process ko CPU milega. Preemptive = OS CPU wapas le sakta hai; non-preemptive = process khatam ya block hone tak CPU rakhta hai.
  • Terms: Arrival Time (AT), Burst Time (BT), Completion Time (CT), Turnaround Time TAT = CT − AT, Waiting Time WT = TAT − BT, Response Time = pehli baar CPU − AT.
  • FCFS: jo pehle aaya wo pehle; simple; convoy effect (chhote jobs lambe job ke peeche atak jaate hain).
  • SJF: sabse chhota burst pehle; minimum average waiting time deta hai; burst estimate chahiye; lambe jobs starve ho sakte hain. Preemptive version = SRTF.
  • Priority: highest priority pehle; starvation aging se fix.
  • Round Robin: har process ko time quantum milta hai, phir queue ke peeche; time-sharing ke liye accha. Quantum bahut bada → FCFS; bahut chhota → bahut context switches.
  • Multilevel Queue / MLFQ: alag policies wali kai queues; MLFQ me process queues ke beech move kar sakta hai.
Example: P1 (AT 0, BT 5), P2 (AT 1, BT 3), P3 (AT 2, BT 1).
FCFS: P1 0–5, P2 5–8, P3 8–9 → WT = 0, 4, 6 → average 3.33.
SJF (non-preemptive): P1 0–5, then P3 5–6, then P2 6–9 → WT = 0, 3 (P3), 5 (P2) → average 2.67. SJF is better.
6. Process Synchronization: Race Condition & Critical Section
ENGLISH
A race condition happens when several processes/threads use shared data and the result depends on the order of execution. Example: two threads do counter++ at once (load, add, store interleave), and one update is lost. The code that touches shared data is the critical section (CS).

A correct CS solution needs: Mutual exclusion (only one inside), Progress (if CS is free, someone waiting should get in), Bounded waiting (no starvation).

  • Peterson’s algorithm: software solution for 2 processes using flag[] and turn.
  • Hardware: atomic Test-and-Set / Compare-and-Swap; disabling interrupts (only single CPU).
  • Mutex (lock): only the owner can unlock; binary. Semaphore: integer with two atomic operations wait(P): while S≤0 wait, then S--; and signal(V): S++. Binary semaphore (0/1) acts like a mutex; counting semaphore manages N identical resources.
  • Monitor: high-level construct; only one process active inside; uses condition variables (wait/signal). Spinlock busy-waits (good for very short waits).
HINGLISH
Race condition tab hoti hai jab kai processes/threads shared data use karte hain aur result execution ke order par depend karta hai. Example: do threads ek saath counter++ karte hain (load, add, store interleave), aur ek update kho jata hai. Jo code shared data chhuta hai wo critical section (CS) hai.

Sahi CS solution ke liye: Mutual exclusion (ek time par ek hi andar), Progress (CS khali ho to wait karne wale ko mile), Bounded waiting (starvation nahi).

  • Peterson’s algorithm: 2 processes ke liye software solution (flag[] aur turn).
  • Hardware: atomic Test-and-Set / Compare-and-Swap; interrupts disable (sirf single CPU par).
  • Mutex (lock): sirf owner unlock kar sakta hai; binary. Semaphore: integer jisme do atomic operations: wait(P): S≤0 ho to wait, phir S--; aur signal(V): S++. Binary semaphore (0/1) mutex jaisa; counting semaphore N identical resources manage karta hai.
  • Monitor: high-level construct; andar ek hi process active; condition variables (wait/signal). Spinlock busy-wait karta hai (bahut chhote wait ke liye accha).
7. Classic Synchronization Problems
ENGLISH
  • Producer–Consumer (bounded buffer): producer adds items, consumer removes. Semaphores: empty = N, full = 0, mutex = 1.
Producer: wait(empty); wait(mutex); add item; signal(mutex); signal(full);
Consumer: wait(full);  wait(mutex); remove item; signal(mutex); signal(empty);
  • Readers–Writers: many readers may read together, but a writer needs exclusive access. Risk: writer starvation (readers-priority) or reader starvation.
  • Dining Philosophers: 5 philosophers, 5 forks; each needs 2 forks. If all pick the left fork, deadlock. Fixes: allow at most 4 to sit, pick both forks only if both free, or odd/even order.
  • Order of wait() matters: doing wait(mutex) before wait(empty) can deadlock.
HINGLISH
  • Producer–Consumer (bounded buffer): producer items daalta hai, consumer nikalta hai. Semaphores: empty = N, full = 0, mutex = 1 (upar ka code dekho).
  • Readers–Writers: kai readers ek saath padh sakte hain, par writer ko akela access chahiye. Risk: writer starvation (readers-priority) ya reader starvation.
  • Dining Philosophers: 5 philosophers, 5 forks; har ko 2 forks chahiye. Sab ne left fork utha li to deadlock. Fix: ek time par max 4 baithein, dono forks free ho tabhi uthao, ya odd/even order.
  • wait() ka order important hai: wait(empty) se pehle wait(mutex) karne par deadlock ho sakta hai.
8. Deadlock: Conditions, Prevention, Avoidance, Detection
ENGLISH
A deadlock is when processes wait forever for resources held by each other.

4 necessary conditions (all must hold): Mutual exclusion, Hold and wait, No preemption, Circular wait.

  • Resource Allocation Graph (RAG): cycle with single-instance resources = deadlock; with multiple instances a cycle is only a possible deadlock.
  • Prevention: break one condition (request all resources at start; allow preemption; impose a global order on resources to stop circular wait).
  • Avoidance: grant a request only if the system stays in a safe state (a safe sequence exists). Banker’s algorithm: Need = Max − Allocation.
  • Detection & recovery: detect (wait-for graph) then kill processes or preempt resources. Ostrich algorithm: ignore it (used by Linux/Windows for rarity).
HINGLISH
Deadlock tab hota hai jab processes ek-dusre ke hold kiye resources ka hamesha wait karte hain.

4 necessary conditions (sab ek saath): Mutual exclusion, Hold and wait, No preemption, Circular wait.

  • Resource Allocation Graph (RAG): single-instance resources me cycle = deadlock; multiple instances me cycle sirf possible deadlock hai.
  • Prevention: koi ek condition todo (shuru me saare resources maango; preemption allow karo; resources ka global order lagao taaki circular wait na ho).
  • Avoidance: request tabhi do jab system safe state me rahe (safe sequence ho). Banker’s algorithm: Need = Max − Allocation.
  • Detection & recovery: detect (wait-for graph), phir processes kill ya resources preempt. Ostrich algorithm: ignore karo (Linux/Windows rare hone ki wajah se).
Banker’s example (1 resource type, total 12): Allocation P0=5, P1=2, P2=3; Max P0=8, P1=4, P2=9; Available = 12 − 10 = 2. Need = 3, 2, 6.
P1 needs 2 ≤ 2, so run P1 → Available 4. P0 needs 3 ≤ 4, run P0 → Available 9. P2 needs 6 ≤ 9, run P2. Safe sequence: <P1, P0, P2>.
9. Memory Management: Allocation & Fragmentation
ENGLISH
  • Logical (virtual) address is generated by the CPU; physical address is the real RAM address. The MMU converts one to the other (base + limit registers in simple schemes).
  • Swapping: move a process to disk and back to free RAM.
  • Contiguous allocation: each process gets one block. Placement: First fit (first hole big enough, fast), Best fit (smallest hole that fits; leaves tiny holes), Worst fit (largest hole).
  • Fragmentation: External (free memory in scattered small holes; fix by compaction or paging) vs Internal (wasted space inside an allocated block, e.g. fixed partitions or the last page).
  • Dynamic loading/linking load routines only when needed. Overlays keep only the needed part in memory.
HINGLISH
  • Logical (virtual) address CPU banata hai; physical address RAM ka asli address hai. MMU ek se dusre me convert karta hai (simple schemes me base + limit registers).
  • Swapping: RAM khali karne ke liye process ko disk par bhejna aur wapas laana.
  • Contiguous allocation: har process ko ek continuous block. Placement: First fit (pehla bada-enough hole, fast), Best fit (sabse chhota hole jo fit ho; chhote bekaar holes bachte hain), Worst fit (sabse bada hole).
  • Fragmentation: External (free memory chhote bikhre holes me; fix compaction ya paging) vs Internal (allocated block ke andar waste jagah, jaise fixed partitions ya last page).
  • Dynamic loading/linking routines tabhi load karte hain jab chahiye. Overlays memory me sirf zaroori hissa rakhte hain.
10. Paging, Segmentation & TLB
ENGLISH
  • Paging: logical memory is split into pages, physical memory into frames of the same size. Any page can go in any frame, so no external fragmentation (only small internal fragmentation). A page table maps page → frame.
  • Address: logical address = page number (p) + offset (d). Physical = frame number × page size + offset.
  • TLB (Translation Lookaside Buffer): a small fast cache of page-table entries. EAT = h×(t + m) + (1−h)×(t + 2m), where h = hit ratio, t = TLB time, m = memory time.
  • Large tables: multilevel (hierarchical) paging, hashed, inverted page table.
  • Segmentation: memory split by logical units (code, stack, data) of different sizes; address = (segment no., offset); has external fragmentation. Segmented paging combines both.
HINGLISH
  • Paging: logical memory pages me aur physical memory same size ke frames me baanti jati hai. Koi bhi page kisi bhi frame me ja sakta hai, isliye external fragmentation nahi (sirf thodi internal). Page table page → frame map karti hai.
  • Address: logical address = page number (p) + offset (d). Physical = frame number × page size + offset.
  • TLB (Translation Lookaside Buffer): page-table entries ka chhota fast cache. EAT = h×(t + m) + (1−h)×(t + 2m); h = hit ratio, t = TLB time, m = memory time.
  • Badi tables: multilevel (hierarchical) paging, hashed, inverted page table.
  • Segmentation: memory logical units (code, stack, data) me alag sizes ke saath; address = (segment no., offset); external fragmentation hoti hai. Segmented paging dono jodta hai.
Example 1: page size 4 KB (4096), logical address 20000 → page = 20000 ÷ 4096 = 4, offset = 20000 − 16384 = 3616. If page 4 is in frame 9, physical = 9×4096 + 3616 = 40480.
Example 2: hit ratio 80%, TLB 20 ns, memory 100 ns: EAT = 0.8×120 + 0.2×220 = 140 ns.
11. Virtual Memory & Page Replacement
ENGLISH
Virtual memory lets a program larger than RAM run by keeping only the needed pages in memory and the rest on disk. It uses demand paging (load a page only when first used).
  • Page fault: the needed page is not in RAM → trap to OS → find page on disk → load into a free frame (or replace one) → update page table → restart the instruction.
  • Page replacement algorithms: FIFO (oldest page out; can show Belady’s anomaly: more frames, more faults), Optimal (replace the page not used for the longest future time; best, but impossible in practice, used as a benchmark), LRU (least recently used; good, needs hardware support), Clock/Second chance.
  • Thrashing: the system spends more time paging than executing (too many processes, too few frames). Fix: reduce multiprogramming, use working-set model or page-fault-frequency control.
  • Locality of reference (programs reuse nearby/recent pages) is why virtual memory works. Copy-on-write shares pages until someone writes.
HINGLISH
Virtual memory RAM se bade program ko chalne deti hai: sirf zaroori pages memory me, baaki disk par. Ye demand paging use karti hai (page pehli baar use hone par hi load).
  • Page fault: zaroori page RAM me nahi → OS ko trap → disk par page dhoondo → free frame me load (ya kisi ko replace) → page table update → instruction dobara chalao.
  • Page replacement algorithms: FIFO (sabse purana page bahar; Belady’s anomaly ho sakti hai: frames badhao to faults badhein), Optimal (jo page sabse der tak use nahi hoga use hatao; best par practically impossible, benchmark), LRU (least recently used; accha, hardware support chahiye), Clock/Second chance.
  • Thrashing: system execution se zyada paging me time lagata hai (bahut processes, kam frames). Fix: multiprogramming kam karo, working-set model ya page-fault-frequency control.
  • Locality of reference (programs paas ke/haal ke pages dobara use karte hain) isi wajah se virtual memory chalti hai. Copy-on-write pages tab tak share karta hai jab tak koi write na kare.
Example: reference string 7 0 1 2 0 3 0 4 2 3 0 3 2 1 2 0 1 7 0 1 with 3 frames: FIFO = 15 faults, LRU = 12 faults, Optimal = 9 faults.
12. File Systems: Allocation, Directories & inode
ENGLISH
  • File: named collection of data. Attributes: name, type, size, location, permissions, timestamps. Operations: create, open, read, write, seek, delete, truncate.
  • Access methods: sequential, direct (random), indexed.
  • Directory structures: single-level, two-level, tree (most common), acyclic graph (links), general graph. Hard link = another name for the same inode; soft (symbolic) link = a pointer to a path.
  • Allocation methods: Contiguous (fast, but external fragmentation and hard to grow), Linked (no fragmentation; slow random access; FAT keeps links in a table), Indexed (index block lists all blocks; supports direct access; Unix inode has direct + single/double/triple indirect pointers).
  • Free-space management: bit vector (bitmap), linked list, grouping, counting.
  • File systems: FAT32, NTFS (Windows), ext4 (Linux), APFS (macOS). Mounting attaches a file system to the directory tree. A journal protects against crashes.
HINGLISH
  • File: data ka naam wala collection. Attributes: name, type, size, location, permissions, timestamps. Operations: create, open, read, write, seek, delete, truncate.
  • Access methods: sequential, direct (random), indexed.
  • Directory structures: single-level, two-level, tree (sabse common), acyclic graph (links), general graph. Hard link = same inode ka dusra naam; soft (symbolic) link = path ka pointer.
  • Allocation methods: Contiguous (fast, par external fragmentation aur badhana mushkil), Linked (fragmentation nahi; random access slow; FAT links ko table me rakhta hai), Indexed (index block saare blocks list karta hai; direct access; Unix inode me direct + single/double/triple indirect pointers).
  • Free-space management: bit vector (bitmap), linked list, grouping, counting.
  • File systems: FAT32, NTFS (Windows), ext4 (Linux), APFS (macOS). Mounting file system ko directory tree se jodta hai. Journal crash se bachata hai.
13. Disk Structure & Disk Scheduling
ENGLISH
Disk access time = seek time (move the arm) + rotational latency + transfer time. Seek time is the biggest, so scheduling tries to reduce head movement.
  • FCFS: in request order; fair, lots of movement. SSTF: nearest request first; less movement, can starve far requests. SCAN (elevator): head sweeps to one end serving requests, then reverses. C-SCAN: sweeps one way only, then jumps back (uniform wait). LOOK / C-LOOK: like SCAN but go only as far as the last request.
  • SSD has no moving parts, so no seek; HDD scheduling matters only for HDDs. RAID 0 (striping), 1 (mirroring), 5 (parity), 10.
HINGLISH
Disk access time = seek time (arm hilana) + rotational latency + transfer time. Seek time sabse bada hai, isliye scheduling head movement kam karne ki koshish karti hai.
  • FCFS: request ke order me; fair, movement zyada. SSTF: sabse nazdeek request pehle; movement kam, door wali requests starve ho sakti hain. SCAN (elevator): head ek end tak requests serve karta hai, phir ulta. C-SCAN: sirf ek direction me sweep, phir wapas jump (wait uniform). LOOK / C-LOOK: SCAN jaisa par aakhri request tak hi jata hai.
  • SSD me moving parts nahi, isliye seek nahi; ye scheduling sirf HDD ke liye. RAID 0 (striping), 1 (mirroring), 5 (parity), 10.
Example: queue 98, 183, 37, 122, 14, 124, 65, 67; head at 53 (cylinders 0–199).
FCFS = 45+85+146+85+108+110+59+2 = 640. SSTF (53→65→67→37→14→98→122→124→183) = 236. SCAN (towards 0 first) = 53 + 183 = 236.
14. I/O Systems: Interrupts, DMA, Buffering & Spooling
ENGLISH
  • Device controller + device driver (OS software) manage each device. Devices are block (disk) or character (keyboard).
  • I/O methods: Polling (CPU keeps checking status; wastes CPU), Interrupt-driven (device signals when done), DMA (Direct Memory Access: a controller moves a whole block between device and memory without the CPU; CPU is interrupted only at the end).
  • Buffering: temporary memory to match speeds between sender and receiver. Caching: keeps a copy of data in faster storage. Spooling: queue jobs for a device that cannot be shared (printer).
  • Memory-mapped I/O uses normal memory addresses for device registers; port-mapped uses special I/O instructions.
HINGLISH
  • Device controller + device driver (OS software) har device ko manage karte hain. Devices block (disk) ya character (keyboard) hote hain.
  • I/O methods: Polling (CPU baar-baar status check karta hai; CPU waste), Interrupt-driven (kaam khatam hone par device signal deta hai), DMA (Direct Memory Access: controller poora block device aur memory ke beech bina CPU ke move karta hai; CPU ko sirf aakhir me interrupt).
  • Buffering: sender aur receiver ki speed match karne ke liye temporary memory. Caching: data ki copy tez storage me. Spooling: jo device share nahi ho sakta (printer) uske liye jobs ki queue.
  • Memory-mapped I/O device registers ke liye normal memory addresses use karta hai; port-mapped special I/O instructions.
15. Protection, Security & Linux Basics
ENGLISH
  • Protection controls access to resources inside the system; security defends against outside threats. Tools: access matrix (domain × object), ACL (per object list), capability list (per user list), user/kernel mode, memory protection.
  • Threats: virus, worm, trojan, ransomware, buffer overflow, privilege escalation. Defences: authentication (password, MFA), least privilege, updates, firewall, encryption.
  • Linux permissions: rwx for owner, group, others. chmod 755 file = rwxr-xr-x (r=4, w=2, x=1).
  • Handy commands: ls, cd, pwd, cat, grep, ps (processes), top, kill PID, chmod, chown, df/du (disk), free (memory), man.
HINGLISH
  • Protection system ke andar resources ka access control karta hai; security bahar ke khatron se bachata hai. Tools: access matrix (domain × object), ACL (har object ki list), capability list (har user ki list), user/kernel mode, memory protection.
  • Threats: virus, worm, trojan, ransomware, buffer overflow, privilege escalation. Defences: authentication (password, MFA), least privilege, updates, firewall, encryption.
  • Linux permissions: owner, group, others ke liye rwx. chmod 755 file = rwxr-xr-x (r=4, w=2, x=1).
  • Kaam ke commands: ls, cd, pwd, cat, grep, ps (processes), top, kill PID, chmod, chown, df/du (disk), free (memory), man.
