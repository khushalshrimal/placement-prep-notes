1. Introduction: Network Types, Topologies & Devices
ENGLISH
A computer network is a set of connected devices that share data and resources.
  • Types by size: PAN (few metres, Bluetooth), LAN (room/building, Ethernet/Wi-Fi), MAN (city), WAN (country/world, the Internet is the biggest WAN).
  • Topologies: Bus (one cable, cheap, one break kills it), Star (all to a central switch; most common, easy to fix, switch is single point of failure), Ring, Mesh (every node linked; very reliable, costly: n(n−1)/2 links), Tree, Hybrid.
  • Transmission modes: simplex (one way, TV), half-duplex (both ways, one at a time, walkie-talkie), full-duplex (both at once, phone).
  • Devices: Hub (L1, repeats to all ports), Switch (L2, forwards by MAC address), Bridge, Router (L3, forwards by IP, connects different networks), Gateway (connects different protocols), Repeater (boosts signal), Modem (digital ↔ analog), Access Point (Wi-Fi).
Client-server (central server serves clients) vs peer-to-peer (every node is both).
HINGLISH
Computer network jude hue devices ka set hai jo data aur resources share karte hain.
  • Size ke hisaab se: PAN (kuch metre, Bluetooth), LAN (room/building, Ethernet/Wi-Fi), MAN (city), WAN (desh/duniya; Internet sabse bada WAN hai).
  • Topologies: Bus (ek cable, sasta, ek jagah tootne par sab band), Star (sab central switch se; sabse common, fix karna easy, switch single point of failure), Ring, Mesh (har node jura hua; bahut reliable, mehenga: n(n−1)/2 links), Tree, Hybrid.
  • Transmission modes: simplex (ek taraf, TV), half-duplex (dono taraf par ek time me ek, walkie-talkie), full-duplex (dono taraf ek saath, phone).
  • Devices: Hub (L1, sab ports par bhejta hai), Switch (L2, MAC address se forward), Bridge, Router (L3, IP se forward, alag networks jodta hai), Gateway (alag protocols jodta hai), Repeater (signal boost), Modem (digital ↔ analog), Access Point (Wi-Fi).
Client-server (central server clients ko serve karta hai) vs peer-to-peer (har node dono kaam karta hai).
2. OSI Model (7 Layers)
ENGLISH
OSI is a reference model that splits communication into 7 layers. Each layer talks to the same layer on the other machine and serves the layer above. Data gets a header added at each layer going down (encapsulation) and removed going up (decapsulation).

Memory trick (top to bottom): All People Seem To Need Data Processing.
HINGLISH
OSI ek reference model hai jo communication ko 7 layers me baantta hai. Har layer dusri machine ki same layer se baat karti hai aur upar wali layer ko service deti hai. Neeche jate waqt har layer header jodti hai (encapsulation) aur upar jate waqt hatati hai (decapsulation).
  • 7 Application: user apps ko services (HTTP, FTP, SMTP, DNS). 6 Presentation: format, encryption, compression (SSL/TLS, JPEG). 5 Session: session shuru, manage, khatam, synchronization.
  • 4 Transport: end-to-end delivery, ports, reliability (TCP, UDP), PDU = segment. 3 Network: IP addressing aur routing (router), PDU = packet. 2 Data Link: framing, MAC address, error detection (switch), PDU = frame. 1 Physical: wire/hawa par bits (cable, hub).

3. TCP/IP Model & OSI vs TCP/IP
ENGLISH
TCP/IP is the practical model the Internet actually uses, with 4 layers: Application (= OSI 5+6+7), Transport (TCP/UDP), Internet (IP, ICMP, ARP; = OSI Network), Network Access / Link (= OSI Data Link + Physical).
  • OSI is a theoretical reference model with 7 layers; TCP/IP is protocol-based, built first, with 4 (or 5) layers.
  • OSI cleanly separates service, interface and protocol; TCP/IP is simpler and is what everyone implements.
  • Many books use a 5-layer model: Application, Transport, Network, Data Link, Physical.
HINGLISH
TCP/IP wo practical model hai jo Internet asal me use karta hai, 4 layers ke saath: Application (= OSI 5+6+7), Transport (TCP/UDP), Internet (IP, ICMP, ARP; = OSI Network), Network Access / Link (= OSI Data Link + Physical).
  • OSI ek theoretical reference model hai (7 layers); TCP/IP protocol-based hai, pehle bana, 4 (ya 5) layers.
  • OSI service, interface aur protocol ko saaf alag karta hai; TCP/IP simple hai aur sab wahi implement karte hain.
  • Kai books 5-layer model use karti hain: Application, Transport, Network, Data Link, Physical.
4. Physical Layer: Media, Switching & Multiplexing
ENGLISH
  • Guided media: twisted pair (UTP/STP, Ethernet cable), coaxial, optical fibre (light, fastest, long distance, immune to noise). Unguided: radio, microwave, infrared, satellite.
  • Switching: Circuit (dedicated path, phone call; fixed delay, wasteful), Packet (data split into packets, shared links; Internet; efficient), Message (store and forward whole message). Packet switching is datagram (each packet routed alone, like IP) or virtual circuit.
  • Multiplexing: many signals on one link. FDM (by frequency), TDM (by time slots), WDM (by light wavelength, fibre).
  • Signals: analog vs digital; bandwidth (Hz) vs bit rate (bps). Nyquist (noiseless): max rate = 2·B·log2L. Shannon (noisy): C = B·log2(1+SNR).
HINGLISH
  • Guided media: twisted pair (UTP/STP, Ethernet cable), coaxial, optical fibre (light, sabse fast, lambi doori, noise-free). Unguided: radio, microwave, infrared, satellite.
  • Switching: Circuit (dedicated path, phone call; delay fixed, resource waste), Packet (data packets me tut kar shared links par; Internet; efficient), Message (poora message store and forward). Packet switching datagram (har packet alag route, jaise IP) ya virtual circuit ho sakti hai.
  • Multiplexing: ek link par kai signals. FDM (frequency se), TDM (time slots se), WDM (light ki wavelength se, fibre).
  • Signals: analog vs digital; bandwidth (Hz) vs bit rate (bps). Nyquist (noise nahi): max rate = 2·B·log2L. Shannon (noise ke saath): C = B·log2(1+SNR).
5. Data Link Layer: Framing & Error Control
ENGLISH
The data link layer moves frames between two directly connected nodes on one link. Jobs: framing, physical (MAC) addressing, error detection, flow control, media access. Two sub-layers: LLC and MAC.
  • Framing: character count, flag bytes with byte stuffing, flag bits with bit stuffing (after five 1s insert a 0).
  • Error detection: Parity bit (catches odd number of bit errors), Checksum (sum of words, used in IP/TCP/UDP), CRC (polynomial division; very strong, used in Ethernet).
  • Error correction: Hamming code adds r parity bits at positions 1,2,4,8… with 2r ≥ m+r+1; it corrects 1-bit errors. Hamming distance d: detects d−1 errors, corrects ⌊(d−1)/2⌋.
CRC example: data 1101, generator 101 → append 2 zeros (110100), divide by XOR; remainder (here 01) is added to the data and sent. Receiver divides again; remainder 0 means no error.
HINGLISH
Data link layer frames ko ek link par seedhe jude do nodes ke beech move karti hai. Kaam: framing, physical (MAC) addressing, error detection, flow control, media access. Do sub-layers: LLC aur MAC.
  • Framing: character count, flag bytes aur byte stuffing, flag bits aur bit stuffing (paanch 1 ke baad 0 daalo).
  • Error detection: Parity bit (odd number of bit errors pakadta hai), Checksum (words ka sum; IP/TCP/UDP me), CRC (polynomial division; bahut strong; Ethernet me).
  • Error correction: Hamming code positions 1,2,4,8… par r parity bits jodta hai jahan 2r ≥ m+r+1; ye 1-bit error theek karta hai. Hamming distance d: d−1 errors detect, ⌊(d−1)/2⌋ correct.
CRC example: data 1101, generator 101 → 2 zeros jodo (110100), XOR division; remainder (yahan 01) data ke saath bhejo. Receiver phir divide karta hai; remainder 0 matlab no error.
6. Flow Control & ARQ (Sliding Window)
ENGLISH
Flow control stops a fast sender from flooding a slow receiver. ARQ (Automatic Repeat reQuest) resends lost or damaged frames using ACKs and timeouts.
  • Stop-and-Wait: send 1 frame, wait for ACK. Simple but wastes time. Efficiency = 1 / (1 + 2a) where a = Tprop/Ttrans.
  • Go-Back-N: sender window up to 2k−1; receiver window = 1. On an error, resend that frame and all after it. Uses cumulative ACKs.
  • Selective Repeat: sender and receiver windows each 2k−1; resend only the lost frame; receiver buffers out-of-order frames.
  • Utilisation of sliding window = N / (1 + 2a), at most 1. Piggybacking: ACK rides inside a data frame going the other way.
HINGLISH
Flow control fast sender ko slow receiver par data baadh ki tarah girane se rokta hai. ARQ (Automatic Repeat reQuest) ACK aur timeout se kho gaye ya kharab frames dobara bhejta hai.
  • Stop-and-Wait: 1 frame bhejo, ACK ka wait. Simple par time waste. Efficiency = 1 / (1 + 2a), a = Tprop/Ttrans.
  • Go-Back-N: sender window 2k−1 tak; receiver window = 1. Error par wo frame aur uske baad ke sab dobara. Cumulative ACK.
  • Selective Repeat: sender aur receiver dono ki window 2k−1; sirf kho gaya frame dobara; receiver out-of-order frames buffer karta hai.
  • Utilisation = N / (1 + 2a), maximum 1. Piggybacking: ACK ulte jaate data frame ke andar hi bhej dena.
7. MAC Layer: Multiple Access, Ethernet & Wi-Fi
ENGLISH
When many nodes share one channel, MAC protocols decide who sends.
  • ALOHA: pure (send any time; max efficiency 18%), slotted (send only at slot start; 37%).
  • CSMA: listen before sending. CSMA/CD (Ethernet, wired): also detects collisions while sending, stops, then waits a random time (binary exponential backoff). Needs frame time ≥ 2×propagation delay.
  • CSMA/CA (Wi-Fi 802.11, wireless): cannot detect collisions, so it avoids them using random backoff and RTS/CTS.
  • Token passing: only the token holder sends (Token Ring); no collisions.
  • Ethernet (802.3): frame = preamble, destination MAC, source MAC, type, data (46–1500 bytes), CRC. MAC address = 48-bit hardware address like AA:BB:CC:11:22:33.
  • Wi-Fi (802.11): a/b/g/n/ac/ax (Wi-Fi 6) differ in speed and band (2.4 GHz, 5 GHz).
HINGLISH
Jab kai nodes ek channel share karte hain to MAC protocols decide karte hain kaun bhejega.
  • ALOHA: pure (kabhi bhi bhejo; max efficiency 18%), slotted (sirf slot ke start par; 37%).
  • CSMA: bhejne se pehle suno. CSMA/CD (Ethernet, wired): bhejte waqt collision bhi detect karta hai, ruk jata hai, phir random time wait (binary exponential backoff). Frame time ≥ 2×propagation delay chahiye.
  • CSMA/CA (Wi-Fi 802.11, wireless): collision detect nahi ho sakta, isliye random backoff aur RTS/CTS se use avoid karta hai.
  • Token passing: sirf token holder bhejta hai (Token Ring); collision nahi.
  • Ethernet (802.3): frame = preamble, destination MAC, source MAC, type, data (46–1500 bytes), CRC. MAC address = 48-bit hardware address, jaise AA:BB:CC:11:22:33.
  • Wi-Fi (802.11): a/b/g/n/ac/ax (Wi-Fi 6) speed aur band (2.4 GHz, 5 GHz) me alag hain.
8. LAN Switching: Switch, VLAN, STP & ARP
ENGLISH
  • Switch learns which MAC is on which port (MAC table) and forwards frames only to the right port. Each port is its own collision domain; the whole switch is one broadcast domain. A router splits broadcast domains.
  • VLAN: splits one physical switch into several logical LANs (e.g. CSE, ECE), improving security and reducing broadcast traffic.
  • STP (Spanning Tree Protocol): blocks redundant links to stop switching loops.
  • ARP: finds the MAC address for a known IP (broadcast “who has 10.0.0.5?”; the owner replies). RARP does the reverse.
HINGLISH
  • Switch seekhta hai kaunsa MAC kis port par hai (MAC table) aur frame sirf sahi port par bhejta hai. Har port apna collision domain hai; poora switch ek broadcast domain. Router broadcast domain todta hai.
  • VLAN: ek physical switch ko kai logical LANs me baantta hai (jaise CSE, ECE); security badhti hai aur broadcast traffic kam hota hai.
  • STP (Spanning Tree Protocol): redundant links block karke switching loops rokta hai.
  • ARP: known IP ka MAC address dhoondta hai (broadcast “10.0.0.5 kiske paas hai?”; owner reply karta hai). RARP ulta karta hai.
9. IP Addressing: IPv4, Classes, Subnetting & CIDR

An IPv4 address is 32 bits (four bytes), like 192.168.1.10. It has a network part and a host part.

HINGLISH

Example: 192.168.1.0/26 → mask 255.255.255.192; host bits = 6, to 26−2 = 62 hosts har subnet me; block size 64 → subnets 192.168.1.0, .64, .128, .192.
10. IPv6, NAT, DHCP & ICMP
ENGLISH
  • IPv6: 128-bit address in hex (2001:db8::1), solves IPv4 shortage, no broadcast, built-in IPsec, simpler header.
  • NAT: maps many private IPs to one public IP (using ports), saving addresses and hiding the internal network.
  • DHCP: gives IP address, mask, gateway and DNS automatically. Steps: DORA = Discover, Offer, Request, Acknowledge.
  • ICMP: error and diagnostic messages. ping (echo request/reply) and traceroute use it.
  • IPv4 header: version, header length, TTL (hop limit; decreases at every router, stops loops), protocol (TCP=6, UDP=17), checksum, source/destination IP. Fragmentation splits packets larger than the link’s MTU.
HINGLISH
  • IPv6: 128-bit hex address (2001:db8::1), IPv4 ki kami door karta hai, broadcast nahi, built-in IPsec, simple header.
  • NAT: kai private IPs ko ek public IP par map karta hai (ports se), addresses bachata hai aur internal network chhupata hai.
  • DHCP: IP address, mask, gateway aur DNS apne aap deta hai. Steps: DORA = Discover, Offer, Request, Acknowledge.
  • ICMP: error aur diagnostic messages. ping (echo request/reply) aur traceroute isi se chalte hain.
  • IPv4 header: version, header length, TTL (har router par kam hota hai, loops rokta hai), protocol (TCP=6, UDP=17), checksum, source/destination IP. Fragmentation link ke MTU se bade packets ko todta hai.
11. Routing: Distance Vector, Link State, RIP, OSPF, BGP
ENGLISH
A router uses a routing table to pick the next hop. Static routes are set by hand; dynamic routes are learned by protocols.
  • Distance Vector (Bellman-Ford): each router tells neighbours its distances to all networks, periodically. Simple but slow to converge; count-to-infinity problem (fixes: split horizon, poison reverse). RIP: hop count, max 15.
  • Link State (Dijkstra): each router floods link information to everyone, builds a full map, and computes shortest paths. Fast convergence, more memory. OSPF is the example.
  • Autonomous System (AS): a network under one administration. Intra-AS (inside): RIP, OSPF. Inter-AS (between ISPs): BGP (path vector, policy-based).
Forwarding = moving a packet to the next hop using the table; routing = building that table.
HINGLISH
Router routing table se next hop chunta hai. Static routes haath se set hote hain; dynamic routes protocols seekhte hain.
  • Distance Vector (Bellman-Ford): har router apne neighbours ko saare networks tak apni distance batata hai, periodically. Simple par converge slow; count-to-infinity problem (fix: split horizon, poison reverse). RIP: hop count, max 15.
  • Link State (Dijkstra): har router link information sabko flood karta hai, poora map banata hai aur shortest path nikalta hai. Convergence fast, memory zyada. Example OSPF.
  • Autonomous System (AS): ek administration ke neeche network. Intra-AS (andar): RIP, OSPF. Inter-AS (ISPs ke beech): BGP (path vector, policy-based).
Forwarding = table dekh kar packet next hop ko bhejna; routing = wo table banana.

  • TCP header: ports, sequence no., ACK no., flags (SYN, ACK, FIN, RST), window size, checksum.
13. TCP Flow & Congestion Control
ENGLISH
  • Flow control: receiver advertises a receive window (rwnd) in every ACK; the sender never has more unACKed data than that.
  • Congestion control: sender keeps a congestion window (cwnd); it sends min(cwnd, rwnd).
  • Slow start: cwnd starts at 1 MSS and doubles every RTT until it reaches ssthresh. Congestion avoidance: then cwnd grows by 1 MSS per RTT (additive increase).
  • On loss: timeout → ssthresh = cwnd/2, cwnd = 1 (back to slow start). 3 duplicate ACKs → fast retransmit and fast recovery (cwnd = ssthresh = cwnd/2). This pattern is AIMD (additive increase, multiplicative decrease).
  • Retransmission timeout is set from the measured RTT. Nagle’s algorithm batches tiny segments.
HINGLISH
  • Flow control: receiver har ACK me receive window (rwnd) batata hai; sender us se zyada unACKed data nahi rakhta.
  • Congestion control: sender congestion window (cwnd) rakhta hai; wo min(cwnd, rwnd) bhejta hai.
  • Slow start: cwnd 1 MSS se shuru aur har RTT me double hota hai jab tak ssthresh na aa jaye. Congestion avoidance: uske baad cwnd har RTT me 1 MSS badhta hai (additive increase).
  • Loss par: timeout → ssthresh = cwnd/2, cwnd = 1 (phir slow start). 3 duplicate ACKs → fast retransmit aur fast recovery (cwnd = ssthresh = cwnd/2). Ye pattern AIMD (additive increase, multiplicative decrease) hai.
  • Retransmission timeout measured RTT se set hota hai. Nagle’s algorithm chhote segments ko jodkar bhejta hai.
14. Application Layer: HTTP, DNS, Email, FTP, SSH
ENGLISH
  • HTTP: request-response, stateless, port 80. Methods: GET (read), POST (create/send), PUT (replace), PATCH (partial update), DELETE. Status codes: 200 OK, 301/302 redirect, 400 bad request, 401 unauthorized, 403 forbidden, 404 not found, 500 server error. HTTP/1.1 keep-alive, HTTP/2 multiplexing, HTTP/3 over QUIC (UDP). HTTPS = HTTP over TLS, port 443. Cookies and sessions add state.
  • DNS: converts a name (google.com) to an IP. Hierarchy: root → TLD (.com) → authoritative server. A recursive resolver asks the chain and caches the answer. Records: A (IPv4), AAAA (IPv6), CNAME (alias), MX (mail), NS. Mostly UDP port 53.
  • Email: SMTP sends (25/587), POP3 downloads and usually deletes from server (110), IMAP syncs mail on server (143).
  • FTP: file transfer, 21 (control) + 20 (data). SSH (22) = secure remote login, replaces Telnet (23, plain text). DHCP uses UDP 67/68.
HINGLISH
  • HTTP: request-response, stateless, port 80. Methods: GET (padhna), POST (bhejna/banana), PUT (replace), PATCH (partial update), DELETE. Status codes: 200 OK, 301/302 redirect, 400 bad request, 401 unauthorized, 403 forbidden, 404 not found, 500 server error. HTTP/1.1 keep-alive, HTTP/2 multiplexing, HTTP/3 QUIC (UDP) par. HTTPS = TLS ke upar HTTP, port 443. Cookies aur sessions state jodte hain.
  • DNS: naam (google.com) ko IP me badalta hai. Hierarchy: root → TLD (.com) → authoritative server. Recursive resolver chain me poochta hai aur answer cache karta hai. Records: A (IPv4), AAAA (IPv6), CNAME (alias), MX (mail), NS. Zyadatar UDP port 53.
  • Email: SMTP bhejta hai (25/587), POP3 download karta hai aur aam taur par server se hata deta hai (110), IMAP server par mail sync rakhta hai (143).
  • FTP: file transfer, 21 (control) + 20 (data). SSH (22) = secure remote login, Telnet (23, plain text) ki jagah. DHCP UDP 67/68 use karta hai.
15. Network Security & Cryptography
ENGLISH
  • Goals (CIA): Confidentiality, Integrity, Availability (+ authentication, non-repudiation).
  • Symmetric encryption: one shared key, fast (AES, DES). Problem: sharing the key safely. Asymmetric: public + private key pair, slower (RSA, ECC); anyone encrypts with your public key, only you decrypt with your private key.
  • Hash (SHA-256): one-way fixed-size fingerprint, checks integrity. Digital signature: hash signed with the sender’s private key gives authenticity + integrity. Certificate (X.509) from a CA binds a public key to an identity.
  • TLS/SSL: handshake uses asymmetric crypto to agree a session key, then fast symmetric encryption protects the data (this is HTTPS).
  • Firewall: filters traffic by rules (packet filter, stateful, application/proxy). VPN: encrypted tunnel over the Internet. IPsec secures the network layer.
  • Attacks: sniffing, spoofing, DoS/DDoS (flood a server), man-in-the-middle, phishing, SQL injection, ARP/DNS poisoning, replay.
HINGLISH
  • Goals (CIA): Confidentiality, Integrity, Availability (+ authentication, non-repudiation).
  • Symmetric encryption: ek shared key, fast (AES, DES). Problem: key safely share karna. Asymmetric: public + private key pair, slow (RSA, ECC); koi bhi tumhari public key se encrypt kare, sirf tum private key se decrypt karoge.
  • Hash (SHA-256): one-way fixed-size fingerprint, integrity check. Digital signature: hash ko sender ki private key se sign karna, authenticity + integrity deta hai. Certificate (X.509) CA ki taraf se public key ko identity se jodta hai.
  • TLS/SSL: handshake me asymmetric crypto se session key tay hoti hai, phir fast symmetric encryption data bachati hai (yahi HTTPS hai).
  • Firewall: rules se traffic filter (packet filter, stateful, application/proxy). VPN: Internet par encrypted tunnel. IPsec network layer secure karta hai.
  • Attacks: sniffing, spoofing, DoS/DDoS (server par flood), man-in-the-middle, phishing, SQL injection, ARP/DNS poisoning, replay.
16. Wireless & Mobile Networks
ENGLISH
  • Wi-Fi (802.11): access point + CSMA/CA; security WEP (weak) → WPA2 → WPA3. Hidden terminal problem: two nodes cannot hear each other but both reach the AP; RTS/CTS helps.
  • Bluetooth: short range, low power, PAN (piconet: 1 master + up to 7 active slaves). Zigbee/NFC/RFID for IoT and tags.
  • Cellular: cell towers reuse frequencies. 2G (voice, GSM), 3G (data), 4G LTE (all-IP, high speed), 5G (very high speed, low latency, IoT). Handoff keeps a call alive while moving between cells.
  • Mobile IP lets a device keep its IP while moving between networks. IoT = billions of small connected devices.
HINGLISH
  • Wi-Fi (802.11): access point + CSMA/CA; security WEP (kamzor) → WPA2 → WPA3. Hidden terminal problem: do nodes ek-dusre ko nahi sun sakte par dono AP tak pahunchte hain; RTS/CTS madad karta hai.
  • Bluetooth: chhoti range, low power, PAN (piconet: 1 master + 7 tak active slaves). Zigbee/NFC/RFID IoT aur tags ke liye.
  • Cellular: cell towers frequencies reuse karte hain. 2G (voice, GSM), 3G (data), 4G LTE (all-IP, high speed), 5G (bahut high speed, low latency, IoT). Handoff cells ke beech move karte waqt call jaari rakhta hai.
  • Mobile IP device ko networks badalne par bhi wahi IP rakhne deta hai. IoT = arabon chhote connected devices.
17. Network Performance: Delay, Throughput & Formulas
ENGLISH
  • Bandwidth: maximum capacity of a link (bps). Throughput: actual rate achieved (≤ bandwidth). Latency: time for data to travel. Jitter: variation in delay. RTT: round-trip time.
  • Total delay = transmission (L / R, packet size ÷ link rate) + propagation (d / s, distance ÷ signal speed) + queuing (waiting in router buffer) + processing (header check, routing).
  • Bandwidth-delay product = bandwidth × RTT = amount of data “in the pipe”.
Example: 1000-byte packet on a 1 Mbps link: Ttrans = 8000 bits / 1,000,000 = 8 ms. If distance is 2000 km and speed 2×108 m/s: Tprop = 2,000,000 / 2×108 = 10 ms.
HINGLISH
  • Bandwidth: link ki maximum capacity (bps). Throughput: asli milne wali speed (≤ bandwidth). Latency: data ko pahunchne me lagne wala time. Jitter: delay ka utar-chadhav. RTT: round-trip time.
  • Total delay = transmission (L / R, packet size ÷ link rate) + propagation (d / s, doori ÷ signal speed) + queuing (router buffer me wait) + processing (header check, routing).
  • Bandwidth-delay product = bandwidth × RTT = pipe me ek saath maujood data.
Example: 1000-byte packet, 1 Mbps link: Ttrans = 8000 bits / 1,000,000 = 8 ms. Doori 2000 km, speed 2×108 m/s ho to Tprop = 2,000,000 / 2×108 = 10 ms.
18. What Happens When You Type a URL? (Top Question)
ENGLISH
Say you type https://www.example.com and press Enter:
  1. Browser cache / DNS: checks caches, then asks a DNS resolver to turn the name into an IP (UDP 53).
  2. ARP: finds the MAC address of the default gateway (router) on your LAN.
  3. TCP handshake: SYN, SYN+ACK, ACK with the server on port 443 (packets travel through routers using IP routing; NAT may rewrite your private IP).
  4. TLS handshake: certificate checked, session key agreed.
  5. HTTP request (GET /) is sent encrypted; server processes it.
  6. HTTP response (status 200 + HTML) returns; browser renders it and fetches CSS, JS and images (more requests).
  7. Connection stays alive or is closed with FIN.
HINGLISH
Maan lo tumne https://www.example.com type karke Enter dabaya:
  1. Browser cache / DNS: caches dekhta hai, phir DNS resolver se naam ka IP poochta hai (UDP 53).
  2. ARP: tumhare LAN me default gateway (router) ka MAC address dhoondta hai.
  3. TCP handshake: server ke port 443 par SYN, SYN+ACK, ACK (packets routers se IP routing ke through jaate hain; NAT tumhara private IP badal sakta hai).
  4. TLS handshake: certificate check, session key tay.
  5. HTTP request (GET /) encrypted bheji jati hai; server process karta hai.
  6. HTTP response (status 200 + HTML) wapas aata hai; browser render karta hai aur CSS, JS, images ke liye aur requests karta hai.
  7. Connection alive rehta hai ya FIN se band hota hai.
19. Top Interview Questions (Quick Revision)
QuestionShort answer (English / Hinglish)
TCP vs UDP?TCP reliable, connection-oriented, slower; UDP unreliable, connectionless, faster. TCP reliable aur slow; UDP fast par best-effort.
Hub vs Switch vs Router?Hub repeats to all (L1); switch forwards by MAC (L2); router forwards by IP (L3). Hub sabko, switch MAC se, router IP se.
MAC vs IP address?MAC = 48-bit physical, fixed to NIC, works inside a LAN; IP = logical, can change, works across networks. MAC hardware ka, IP network ka.
What is ARP?Maps an IP to a MAC address inside a LAN. IP se MAC nikalta hai.
What is a subnet mask?Marks which bits are network and which are host. Network aur host bits alag batata hai.
Private vs public IP?Private works only inside a LAN (10.x, 172.16-31.x, 192.168.x); public is unique on the Internet; NAT connects them. Private LAN ke andar, public Internet par.
What is DNS?Turns domain names into IP addresses. Naam ko IP me badalta hai.
GET vs POST?GET reads data, params in URL, cacheable; POST sends data in body, not cached. GET padhta hai, POST data bhejta hai.
TCP 3-way handshake?SYN, SYN+ACK, ACK. Connection kholne ke 3 steps.
Distance vector vs link state?DV shares table with neighbours (Bellman-Ford); LS floods link info to all (Dijkstra). DV neighbours se, LS sabse.
What is a firewall?Filters traffic by rules to protect a network. Rules se traffic rokta hai.
HTTP vs HTTPS?HTTPS = HTTP + TLS encryption (port 443). HTTPS encrypted hota hai.
Collision domain vs broadcast domain?Switch port = own collision domain; router port = own broadcast domain. Switch collision todta hai, router broadcast.
What is TTL?Hop limit in IP header, reduced at each router, packet dropped at 0. Packet ki life; 0 par drop.
