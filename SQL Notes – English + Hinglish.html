1. Introduction to SQL & Setup
ENGLISH
SQL (Structured Query Language) is the standard language to talk to relational databases (MySQL, PostgreSQL, SQL Server, Oracle, SQLite). It is declarative: you say what you want, not how to get it.
  • Command groups: DDL (CREATE, ALTER, DROP, TRUNCATE), DML (INSERT, UPDATE, DELETE), DQL (SELECT), DCL (GRANT, REVOKE), TCL (COMMIT, ROLLBACK, SAVEPOINT).
  • SQL keywords are not case-sensitive; end statements with ;. Text values use single quotes ‘Amit’. Comments: -- one line and /* block */.
  • Small differences exist between databases (LIMIT vs TOP vs FETCH FIRST, AUTO_INCREMENT vs SERIAL). These notes mostly use MySQL/PostgreSQL style.
HINGLISH
SQL (Structured Query Language) relational databases se baat karne ki standard language hai (MySQL, PostgreSQL, SQL Server, Oracle, SQLite). Ye declarative hai: tum batate ho kya chahiye, kaise nahi.
  • Command groups: DDL (CREATE, ALTER, DROP, TRUNCATE), DML (INSERT, UPDATE, DELETE), DQL (SELECT), DCL (GRANT, REVOKE), TCL (COMMIT, ROLLBACK, SAVEPOINT).
  • SQL keywords case-sensitive nahi; statement ; se khatam karo. Text values single quotes me ‘Amit’. Comments: -- ek line aur /* block */.
  • Databases me thode fark hote hain (LIMIT vs TOP vs FETCH FIRST, AUTO_INCREMENT vs SERIAL). Ye notes zyadatar MySQL/PostgreSQL style me hain.

2. DDL: CREATE, ALTER, DROP, Data Types & Constraints
ENGLISH
  • Data types: INT, BIGINT, DECIMAL(p,s), FLOAT, CHAR(n) (fixed), VARCHAR(n) (variable), TEXT, DATE, DATETIME/TIMESTAMP, BOOLEAN.
  • Constraints: PRIMARY KEY, FOREIGN KEY, UNIQUE, NOT NULL, CHECK, DEFAULT, AUTO_INCREMENT.
  • ALTER: ADD COLUMN, MODIFY/ALTER COLUMN, DROP COLUMN, RENAME. DROP removes the whole table; TRUNCATE removes all rows fast (resets counters, cannot be rolled back in many DBs); DELETE removes chosen rows.
HINGLISH
  • Data types: INT, BIGINT, DECIMAL(p,s), FLOAT, CHAR(n) (fixed), VARCHAR(n) (variable), TEXT, DATE, DATETIME/TIMESTAMP, BOOLEAN.
  • Constraints: PRIMARY KEY, FOREIGN KEY, UNIQUE, NOT NULL, CHECK, DEFAULT, AUTO_INCREMENT.
  • ALTER: ADD COLUMN, MODIFY/ALTER COLUMN, DROP COLUMN, RENAME. DROP poori table hatata hai; TRUNCATE saari rows jaldi hata deta hai (counters reset, kai DBs me rollback nahi); DELETE chuni hui rows hatata hai.
CREATE TABLE Department (
    dept_id   VARCHAR(5) PRIMARY KEY,
    dept_name VARCHAR(50) NOT NULL UNIQUE
);
CREATE TABLE Employee (
    emp_id     INT PRIMARY KEY AUTO_INCREMENT,
    name       VARCHAR(50) NOT NULL,
    dept_id    VARCHAR(5),
    salary     DECIMAL(10,2) CHECK (salary >= 0) DEFAULT 0,
    manager_id INT,
    city       VARCHAR(30),
    FOREIGN KEY (dept_id)    REFERENCES Department(dept_id) ON DELETE SET NULL,
    FOREIGN KEY (manager_id) REFERENCES Employee(emp_id)
);
ALTER TABLE Employee ADD COLUMN email VARCHAR(80);
ALTER TABLE Employee DROP COLUMN email;
TRUNCATE TABLE Employee;   DROP TABLE Employee;
3. DML: INSERT, UPDATE, DELETE
ENGLISH
  • INSERT adds rows (name the columns, it is safer). UPDATE changes rows; always use WHERE or every row changes. DELETE removes rows; also needs WHERE.
  • Tip: first run a SELECT with the same WHERE to see which rows will be affected.
  • Upsert (insert or update): MySQL ON DUPLICATE KEY UPDATE, PostgreSQL ON CONFLICT DO UPDATE. INSERT … SELECT copies rows from another table.
HINGLISH
  • INSERT rows jodta hai (columns ke naam likho, safer hai). UPDATE rows badalta hai; WHERE zaroor lagao warna saari rows badal jaati hain. DELETE rows hatata hai; usme bhi WHERE chahiye.
  • Tip: pehle same WHERE ke saath SELECT chalao dekhne ke liye kaunsi rows affect hongi.
  • Upsert (insert ya update): MySQL ON DUPLICATE KEY UPDATE, PostgreSQL ON CONFLICT DO UPDATE. INSERT … SELECT dusri table se rows copy karta hai.
INSERT INTO Department VALUES ('d1','IT'), ('d2','HR'), ('d3','Finance'), ('d4','Sales');
INSERT INTO Employee (name, dept_id, salary, city) VALUES ('Amit','d1',50000,'Jaipur');

UPDATE Employee SET salary = salary * 1.10 WHERE dept_id = 'd1';   -- 10% hike for IT
DELETE FROM Employee WHERE emp_id = 6;
4. SELECT Basics: WHERE, LIKE, IN, BETWEEN, ORDER BY, LIMIT
ENGLISH
  • SELECT col1, col2 FROM table; * = all columns (avoid in real code). DISTINCT removes duplicates. AS gives an alias.
  • WHERE operators: = <> < > <= >=, AND OR NOT, IN (list), BETWEEN a AND b (inclusive), LIKE (% = any text, _ = one char), IS NULL / IS NOT NULL.
  • ORDER BY col ASC (default) or DESC. LIMIT n OFFSET m (MySQL/PostgreSQL) = pagination; SQL Server uses TOP n; standard SQL uses FETCH FIRST n ROWS ONLY.
  • Written order: SELECT → FROM → WHERE → GROUP BY → HAVING → ORDER BY → LIMIT.
HINGLISH
  • SELECT col1, col2 FROM table; * = saare columns (asli code me avoid). DISTINCT duplicates hatata hai. AS alias deta hai.
  • WHERE operators: = <> < > <= >=, AND OR NOT, IN (list), BETWEEN a AND b (dono end shamil), LIKE (% = koi bhi text, _ = ek character), IS NULL / IS NOT NULL.
  • ORDER BY col ASC (default) ya DESC. LIMIT n OFFSET m (MySQL/PostgreSQL) = pagination; SQL Server me TOP n; standard SQL me FETCH FIRST n ROWS ONLY.
  • Likhne ka order: SELECT → FROM → WHERE → GROUP BY → HAVING → ORDER BY → LIMIT.
SELECT DISTINCT city FROM Employee;                          -- Jaipur, Delhi, Mumbai
SELECT name, salary AS pay FROM Employee WHERE salary BETWEEN 40000 AND 60000;
SELECT * FROM Employee WHERE name LIKE 'R%';                 -- Riya, Rohit
SELECT * FROM Employee WHERE city IN ('Delhi','Mumbai') AND dept_id IS NOT NULL;
SELECT name FROM Employee ORDER BY salary DESC, name ASC LIMIT 3 OFFSET 0;
5. Functions, CASE & NULL Handling
ENGLISH
  • Aggregate: COUNT, SUM, AVG, MIN, MAX. COUNT(*) counts all rows; COUNT(col) skips NULLs; COUNT(DISTINCT col) counts unique values.
  • String: UPPER, LOWER, LENGTH, CONCAT, SUBSTRING, TRIM, REPLACE. Numeric: ROUND, CEIL, FLOOR, ABS, MOD. Date: NOW(), CURDATE(), DATE_ADD, DATEDIFF, YEAR(), MONTH() (names vary by DB).
  • NULL means unknown. NULL = NULL is not true; use IS NULL. Any arithmetic with NULL gives NULL. COALESCE(a,b,c) returns the first non-NULL; IFNULL / NVL for two values. NULLIF(a,b) returns NULL if equal (avoid divide by zero).
  • CASE is SQL’s if-else.
HINGLISH
  • Aggregate: COUNT, SUM, AVG, MIN, MAX. COUNT(*) saari rows ginta hai; COUNT(col) NULL skip karta hai; COUNT(DISTINCT col) unique values ginta hai.
  • String: UPPER, LOWER, LENGTH, CONCAT, SUBSTRING, TRIM, REPLACE. Numeric: ROUND, CEIL, FLOOR, ABS, MOD. Date: NOW(), CURDATE(), DATE_ADD, DATEDIFF, YEAR(), MONTH() (naam DB ke hisaab se badalte hain).
  • NULL matlab unknown. NULL = NULL true nahi hota; IS NULL use karo. NULL ke saath koi bhi arithmetic NULL deta hai. COALESCE(a,b,c) pehli non-NULL value deta hai; IFNULL / NVL do values ke liye. NULLIF(a,b) barabar ho to NULL deta hai (divide by zero se bachne ke liye).
  • CASE SQL ka if-else hai.
SELECT name,
       CASE WHEN salary >= 60000 THEN 'High'
            WHEN salary >= 40000 THEN 'Medium'
            ELSE 'Low' END AS grade,
       COALESCE(dept_id, 'No Dept') AS dept
FROM Employee;
SELECT COUNT(*) AS total, COUNT(dept_id) AS with_dept FROM Employee;   -- 6 and 5
6. GROUP BY, HAVING & Order of Execution
ENGLISH
GROUP BY puts rows with the same value into groups so aggregate functions work per group. Every non-aggregated column in SELECT must be in GROUP BY. WHERE filters rows before grouping; HAVING filters groups after grouping (can use aggregates).

Logical execution order (very common question): FROM/JOIN → WHERE → GROUP BY → HAVING → SELECT → DISTINCT → ORDER BY → LIMIT. That is why a column alias from SELECT can be used in ORDER BY but not in WHERE.

HINGLISH
GROUP BY same value wali rows ko groups me daalta hai taaki aggregate functions har group par chalein. SELECT ka har non-aggregated column GROUP BY me hona chahiye. WHERE grouping se pehle rows filter karta hai; HAVING grouping ke baad groups filter karta hai (aggregates use kar sakta hai).

Logical execution order (bahut common sawaal): FROM/JOIN → WHERE → GROUP BY → HAVING → SELECT → DISTINCT → ORDER BY → LIMIT. Isliye SELECT ka alias ORDER BY me chalta hai par WHERE me nahi.

SELECT dept_id, COUNT(*) AS emp_count, AVG(salary) AS avg_sal
FROM Employee
WHERE city <> 'Mumbai'          -- row filter first
GROUP BY dept_id
HAVING AVG(salary) > 45000      -- group filter after
ORDER BY avg_sal DESC;
7. Joins: INNER, LEFT, RIGHT, FULL, CROSS, SELF
ENGLISH
A join combines rows of two tables using a related column (usually a foreign key).
  • INNER JOIN: only matching rows. LEFT JOIN: all left rows + matches (NULL if none). RIGHT JOIN: all right rows + matches. FULL OUTER JOIN: all rows from both (MySQL: LEFT UNION RIGHT). CROSS JOIN: every row with every row (m × n). SELF JOIN: a table joined with itself using aliases.
  • Find unmatched rows: LEFT JOIN and filter WHERE right.key IS NULL.
  • ON vs WHERE: for LEFT JOIN, a condition on the right table in WHERE turns it into an INNER JOIN; put it in ON instead. USING(col) and NATURAL JOIN are shortcuts (NATURAL is risky).
HINGLISH
Join do tables ki rows ko related column (aksar foreign key) se jodta hai.
  • INNER JOIN: sirf matching rows. LEFT JOIN: left ki saari rows + matches (na mile to NULL). RIGHT JOIN: right ki saari rows + matches. FULL OUTER JOIN: dono ki saari rows (MySQL me LEFT UNION RIGHT). CROSS JOIN: har row ka har row se combination (m × n). SELF JOIN: table apne aap se join, aliases ke saath.
  • Unmatched rows dhoondhna: LEFT JOIN karo aur WHERE right.key IS NULL lagao.
  • ON vs WHERE: LEFT JOIN me right table ki condition WHERE me lagaoge to wo INNER JOIN ban jata hai; use ON me lagao. USING(col) aur NATURAL JOIN shortcuts hain (NATURAL risky).
-- employee with department name (Sara has no dept, so she is dropped)
SELECT e.name, d.dept_name
FROM Employee e INNER JOIN Department d ON e.dept_id = d.dept_id;

-- all employees, even without dept
SELECT e.name, d.dept_name
FROM Employee e LEFT JOIN Department d ON e.dept_id = d.dept_id;   -- Sara | NULL

-- departments with no employees  ->  Sales
SELECT d.dept_name
FROM Department d LEFT JOIN Employee e ON d.dept_id = e.dept_id
WHERE e.emp_id IS NULL;

-- employee and manager (self join)
SELECT e.name AS employee, m.name AS manager
FROM Employee e LEFT JOIN Employee m ON e.manager_id = m.emp_id;
8. Subqueries, EXISTS & Correlated Subqueries
ENGLISH
A subquery is a query inside another query (in WHERE, FROM or SELECT).
  • Scalar (returns 1 value): salary > (SELECT AVG(salary) FROM Employee). Multi-row: use IN, ANY, ALL. Derived table: subquery in FROM, needs an alias.
  • Correlated subquery uses a column from the outer query and runs once per outer row (slower). EXISTS returns true if the subquery returns any row; usually faster than IN for large data and safe with NULLs. NOT IN breaks if the list contains NULL; prefer NOT EXISTS.
  • Many subqueries can be rewritten as JOINs or CTEs for speed and clarity.
HINGLISH
Subquery ek query ke andar doosri query hai (WHERE, FROM ya SELECT me).
  • Scalar (1 value deta hai): salary > (SELECT AVG(salary) FROM Employee). Multi-row: IN, ANY, ALL use karo. Derived table: FROM me subquery, alias zaroori.
  • Correlated subquery outer query ka column use karti hai aur har outer row ke liye chalti hai (slow). EXISTS true deta hai agar subquery koi bhi row de; bade data par aksar IN se fast aur NULL se safe. NOT IN list me NULL ho to toot jata hai; NOT EXISTS prefer karo.
  • Kai subqueries ko JOIN ya CTE me likhna fast aur saaf hota hai.
-- earns more than average (avg = 51666) -> Riya, Neha, Rohit
SELECT name FROM Employee WHERE salary > (SELECT AVG(salary) FROM Employee);

-- people who are managers -> Amit, Riya, Karan
SELECT name FROM Employee e
WHERE EXISTS (SELECT 1 FROM Employee x WHERE x.manager_id = e.emp_id);

-- correlated: earns more than average of own department
SELECT name FROM Employee e
WHERE salary > (SELECT AVG(salary) FROM Employee WHERE dept_id = e.dept_id);
9. Set Operations, CTE & Views
ENGLISH
  • UNION (combine, remove duplicates), UNION ALL (keep duplicates, faster), INTERSECT (common rows), EXCEPT / MINUS (in first, not in second). Both queries need the same number and compatible types of columns.
  • CTE (WITH name AS (…)) is a named temporary result; makes long queries readable. Recursive CTE walks hierarchies (manager tree).
  • View: a saved SELECT that behaves like a virtual table (hide columns, simplify joins, security). Most simple views are updatable; materialized view stores the result physically and must be refreshed.
HINGLISH
  • UNION (jodo, duplicates hatao), UNION ALL (duplicates rakho, fast), INTERSECT (common rows), EXCEPT / MINUS (pehli me hai, dusri me nahi). Dono queries me columns ki ginti same aur types compatible hone chahiye.
  • CTE (WITH name AS (…)) naam wala temporary result hai; lambi query readable banata hai. Recursive CTE hierarchy (manager tree) ghoomta hai.
  • View: saved SELECT jo virtual table ki tarah kaam karta hai (columns chhupao, joins simple karo, security). Zyadatar simple views updatable hote hain; materialized view result ko physically store karta hai aur refresh karna padta hai.
WITH dept_avg AS (
    SELECT dept_id, AVG(salary) AS avg_sal FROM Employee GROUP BY dept_id
)
SELECT e.name, e.salary, d.avg_sal
FROM Employee e JOIN dept_avg d ON e.dept_id = d.dept_id
WHERE e.salary > d.avg_sal;                       -- result: Amit (IT avg = 45000)

CREATE VIEW high_paid AS
SELECT name, salary FROM Employee WHERE salary >= 60000;
SELECT * FROM high_paid;                          -- Riya, Neha, Rohit
10. Window Functions
ENGLISH
Window functions calculate over a set of rows related to the current row without collapsing them (unlike GROUP BY). Syntax: func() OVER (PARTITION BY col ORDER BY col).
  • Ranking: ROW_NUMBER() (1,2,3,4), RANK() (1,1,3,4: gaps after ties), DENSE_RANK() (1,1,2,3: no gaps), NTILE(n) (buckets).
  • Value access: LAG(col) (previous row), LEAD(col) (next row), FIRST_VALUE, LAST_VALUE.
  • Aggregates as windows: SUM(x) OVER (ORDER BY id) = running total; AVG(x) OVER (PARTITION BY dept) = dept average beside each row.
HINGLISH
Window functions current row se related rows ke set par calculate karte hain bina rows ko collapse kiye (GROUP BY ke ulta). Syntax: func() OVER (PARTITION BY col ORDER BY col).
  • Ranking: ROW_NUMBER() (1,2,3,4), RANK() (1,1,3,4: tie ke baad gap), DENSE_RANK() (1,1,2,3: gap nahi), NTILE(n) (buckets).
  • Value access: LAG(col) (pichhli row), LEAD(col) (agli row), FIRST_VALUE, LAST_VALUE.
  • Aggregates as windows: SUM(x) OVER (ORDER BY id) = running total; AVG(x) OVER (PARTITION BY dept) = har row ke saath dept average.
SELECT name, dept_id, salary,
       RANK()       OVER (PARTITION BY dept_id ORDER BY salary DESC) AS rnk,
       SUM(salary)  OVER (ORDER BY emp_id)                           AS running_total,
       LAG(salary)  OVER (ORDER BY emp_id)                           AS prev_salary
FROM Employee;
-- Nth highest salary (N = 2) -> 60000
SELECT DISTINCT salary FROM (
  SELECT salary, DENSE_RANK() OVER (ORDER BY salary DESC) AS r FROM Employee) t
WHERE r = 2;
11. Indexes, Constraints & Query Performance
ENGLISH
  • Index: a lookup structure (usually B+ tree) that speeds up WHERE, JOIN, ORDER BY on a column; slows down INSERT/UPDATE slightly and uses space. PRIMARY KEY and UNIQUE create indexes automatically. Composite index follows the leftmost prefix rule.
  • Write fast queries: select only needed columns, filter early, index join/filter columns, avoid functions on indexed columns (WHERE YEAR(d)=2026 kills the index; use a date range), avoid leading wildcard LIKE ‘%abc’, use EXISTS over IN for big lists, use LIMIT.
  • EXPLAIN shows the execution plan (index used? full scan?). Normalization reduces duplicates; denormalization speeds up reads.
HINGLISH
  • Index: lookup structure (aksar B+ tree) jo column par WHERE, JOIN, ORDER BY ko fast karta hai; INSERT/UPDATE thoda slow aur extra space. PRIMARY KEY aur UNIQUE index khud banate hain. Composite index me leftmost prefix rule.
  • Fast queries ke tareeke: sirf zaroori columns select karo, jaldi filter, join/filter columns par index, indexed column par function mat lagao (WHERE YEAR(d)=2026 index kharab karta hai; date range use karo), shuru me wildcard wala LIKE ‘%abc’ avoid, bade lists ke liye IN ki jagah EXISTS, LIMIT lagao.
  • EXPLAIN execution plan dikhata hai (index use hua? full scan?). Normalization duplicates kam karta hai; denormalization read fast karta hai.
CREATE INDEX idx_dept_city ON Employee (dept_id, city);   -- helps dept_id, or dept_id+city
EXPLAIN SELECT * FROM Employee WHERE dept_id = 'd1';
12. Transactions, TCL & DCL
ENGLISH
  • Transaction = group of statements that succeed or fail together (ACID: Atomicity, Consistency, Isolation, Durability). START TRANSACTION / BEGIN, COMMIT (save), ROLLBACK (undo), SAVEPOINT name + ROLLBACK TO name. Many DBs auto-commit each statement by default.
  • Isolation levels: Read Uncommitted → Read Committed → Repeatable Read → Serializable (prevent dirty, non-repeatable and phantom reads). Locks and deadlocks can occur.
  • DCL: GRANT SELECT, INSERT ON db.Employee TO user; REVOKE. Give least privilege.
HINGLISH
  • Transaction = statements ka group jo saath safal ya saath fail hote hain (ACID: Atomicity, Consistency, Isolation, Durability). START TRANSACTION / BEGIN, COMMIT (save), ROLLBACK (undo), SAVEPOINT name + ROLLBACK TO name. Kai DBs me har statement default me auto-commit hota hai.
  • Isolation levels: Read Uncommitted → Read Committed → Repeatable Read → Serializable (dirty, non-repeatable aur phantom reads rokte hain). Locks aur deadlocks ho sakte hain.
  • DCL: GRANT SELECT, INSERT ON db.Employee TO user; REVOKE. Kam se kam privilege do.
START TRANSACTION;
UPDATE Account SET balance = balance - 500 WHERE id = 'A';
UPDATE Account SET balance = balance + 500 WHERE id = 'B';
COMMIT;      -- or ROLLBACK; if something fails
13. Stored Procedures, Functions, Triggers & Cursors
ENGLISH
  • Stored procedure: saved SQL code you call with CALL name(args); can take IN/OUT parameters, may change data. Function: returns a value and is used inside queries. Benefits: reuse, speed, security, less network traffic.
  • Trigger: runs automatically BEFORE/AFTER INSERT/UPDATE/DELETE (audit logs, validation). Use carefully; hidden logic is hard to debug.
  • Cursor: processes query rows one by one (slow; prefer set-based SQL).
HINGLISH
  • Stored procedure: saved SQL code jise CALL name(args) se chalate hain; IN/OUT parameters le sakta hai, data badal sakta hai. Function: value return karta hai aur queries ke andar use hota hai. Fayde: reuse, speed, security, kam network traffic.
  • Trigger: BEFORE/AFTER INSERT/UPDATE/DELETE par apne aap chalta hai (audit logs, validation). Dhyaan se use karo; chhupa logic debug karna mushkil.
  • Cursor: query ki rows ko ek-ek karke process karta hai (slow; set-based SQL prefer karo).
DELIMITER //
CREATE PROCEDURE raise_salary(IN d VARCHAR(5), IN pct DECIMAL(5,2))
BEGIN
    UPDATE Employee SET salary = salary * (1 + pct/100) WHERE dept_id = d;
END //
DELIMITER ;
CALL raise_salary('d1', 10);

CREATE TRIGGER log_delete AFTER DELETE ON Employee
FOR EACH ROW INSERT INTO audit_log (emp_id, action) VALUES (OLD.emp_id, 'deleted');
14. Practice: 16 Interview Queries (try first, then reveal)
Cover the answer, write the query yourself, then tap Show answer. Use the sample tables in topic 1.
1. Employees who live in Jaipur.
SELECT * FROM Employee WHERE city = 'Jaipur';
Result: Amit, Karan, Sara
2. Number of employees in each department.
SELECT dept_id, COUNT(*) AS cnt FROM Employee GROUP BY dept_id;
Result: d1: 2, d2: 2, d3: 1, NULL: 1
3. Departments whose average salary is more than 45000.
SELECT dept_id, AVG(salary) FROM Employee GROUP BY dept_id HAVING AVG(salary) > 45000;
Result: d2 (60000), d3 (70000)
4. Second highest salary.
SELECT MAX(salary) FROM Employee WHERE salary < (SELECT MAX(salary) FROM Employee);
Result: 60000
5. Employees without any department.
SELECT name FROM Employee WHERE dept_id IS NULL;
Result: Sara
6. Departments that have no employees.
SELECT d.dept_name FROM Department d LEFT JOIN Employee e ON d.dept_id = e.dept_id WHERE e.emp_id IS NULL;
Result: Sales
7. Employee name with manager name.
SELECT e.name, m.name AS manager FROM Employee e LEFT JOIN Employee m ON e.manager_id = m.emp_id;
Result: Amit-NULL, Riya-Amit, Karan-Amit, Neha-Riya, Rohit-Riya, Sara-Karan
8. Salaries that appear more than once.
SELECT salary, COUNT(*) FROM Employee GROUP BY salary HAVING COUNT(*) > 1;
Result: 60000 (2 times: Riya, Rohit)
9. Employees earning more than the company average.
SELECT name FROM Employee WHERE salary > (SELECT AVG(salary) FROM Employee);
Result: Riya, Neha, Rohit (average is about 51667)
10. Total salary spent per city.
SELECT city, SUM(salary) AS total FROM Employee GROUP BY city;
Result: Jaipur 120000, Delhi 120000, Mumbai 70000
11. Top 3 highest paid employees (ties included).
SELECT name, salary FROM (SELECT name, salary, DENSE_RANK() OVER (ORDER BY salary DESC) r FROM Employee) t WHERE r <= 3;
Result: Neha 70000, Riya 60000, Rohit 60000, Amit 50000
12. Highest paid employee in each department.
SELECT * FROM (SELECT name, dept_id, salary, RANK() OVER (PARTITION BY dept_id ORDER BY salary DESC) r FROM Employee WHERE dept_id IS NOT NULL) t WHERE r = 1;
Result: Amit (d1), Riya and Rohit (d2, tie), Neha (d3)
13. Running total of salary by emp_id.
SELECT name, SUM(salary) OVER (ORDER BY emp_id) AS running FROM Employee;
Result: 50000, 110000, 150000, 220000, 280000, 310000
14. Department(s) with the most employees.
SELECT dept_id FROM Employee WHERE dept_id IS NOT NULL GROUP BY dept_id HAVING COUNT(*) = (SELECT MAX(c) FROM (SELECT COUNT(*) c FROM Employee WHERE dept_id IS NOT NULL GROUP BY dept_id) x);
Result: d1 and d2 (2 each)
15. Delete duplicate rows, keep the lowest id (by email).
DELETE FROM Employee WHERE emp_id NOT IN (SELECT MIN(emp_id) FROM (SELECT * FROM Employee) t GROUP BY email);
Result: Keeps one row per email (MySQL needs the derived-table trick)
16. How many employees have no department (using counts)?
SELECT COUNT(*) - COUNT(dept_id) AS no_dept FROM Employee;
Result: 1
15. Top Interview Questions (Quick Revision)
QuestionShort answer (English / Hinglish)
DELETE vs TRUNCATE vs DROP?Delete some rows (WHERE, rollback possible); truncate all rows fast; drop the whole table. Kuch rows / saari rows jaldi / poori table.
WHERE vs HAVING?WHERE filters rows before grouping; HAVING filters groups after. WHERE rows par, HAVING groups par.
INNER vs LEFT JOIN?INNER keeps matches only; LEFT keeps all left rows. INNER sirf match, LEFT left ki sab rows.
UNION vs UNION ALL?UNION removes duplicates; UNION ALL keeps them and is faster. UNION duplicates hatata hai.
Primary key vs Unique key?Primary: unique + not null, one per table. Unique: allows NULL, many allowed. Primary ek, unique kai.
RANK vs DENSE_RANK vs ROW_NUMBER?1,1,3 vs 1,1,2 vs 1,2,3. Tie par gap, bina gap, ya unique number.
COUNT(*) vs COUNT(col)?COUNT(*) counts all rows; COUNT(col) skips NULLs. COUNT(col) NULL ignore karta hai.
IN vs EXISTS?IN compares to a list; EXISTS checks if any row exists, safer with NULLs. EXISTS bade data aur NULL ke liye behtar.
What is a view?Saved query acting as a virtual table. Virtual table.
Clustered vs non-clustered index?Clustered sets physical row order (one per table); non-clustered is a separate structure (many). Clustered ek, non-clustered kai.
What is a CTE?Named temporary result defined with WITH. WITH se naam wala temporary result.
Stored procedure vs function?Procedure is called with CALL and can change data; function returns a value and is used in queries. Procedure CALL se, function query me.
What is normalization?Organising tables to remove redundancy (1NF, 2NF, 3NF, BCNF). Repetition hatane ke liye tables todna.
How to find duplicates?GROUP BY the column and HAVING COUNT(*) > 1. GROUP BY + HAVING COUNT(*) > 1.
NULL comparison?Use IS NULL, not = NULL. = NULL kabhi true nahi hota.
Order of execution of a query?FROM, WHERE, GROUP BY, HAVING, SELECT, ORDER BY, LIMIT. Ye logical order hai.
