1. Introduction: Procedural vs OOP & the 4 Pillars
ENGLISH
OOP (Object-Oriented Programming) organises a program as objects (data + the functions that work on it) instead of a list of functions acting on separate data (procedural, like C).
  • Class = blueprint/template. Object = a real instance made from the class (class Car; object myCar).
  • Encapsulation: wrap data and functions in one unit and hide the data (private).
  • Abstraction: show only what is needed, hide the how (you press the brake, not worry about hydraulics).
  • Inheritance: a new class reuses an existing class (Dog is an Animal).
  • Polymorphism: one name, many forms (same call, different behaviour).
Benefits: reusability, maintainability, security through data hiding, closer to real world. C++ vs C: C++ adds classes, OOP, references, templates, STL, exceptions, namespaces. C++ is multi-paradigm (not purely OOP).
HINGLISH
OOP (Object-Oriented Programming) program ko objects (data + us par kaam karne wale functions) me organise karta hai, na ki alag data par chalte functions ki list (procedural, jaise C).
  • Class = blueprint/template. Object = class se bana asli instance (class Car; object myCar).
  • Encapsulation: data aur functions ko ek unit me bandhna aur data chhupana (private).
  • Abstraction: sirf zaroori cheez dikhana, kaise hota hai wo chhupana (tum brake dabate ho, hydraulics ki chinta nahi).
  • Inheritance: nayi class purani class ko reuse karti hai (Dog ek Animal hai).
  • Polymorphism: ek naam, kai roop (same call, alag behaviour).
Fayde: reusability, maintainability, data hiding se security, real world ke kareeb. C++ vs C: C++ me classes, OOP, references, templates, STL, exceptions, namespaces hain. C++ multi-paradigm hai (poori tarah OOP nahi).
#include <iostream>
using namespace std;

class Student {            // class = blueprint
public:
    string name;
    int marks;
    void show() { cout << name << " : " << marks << endl; }
};

int main() {
    Student s1;            // object = instance
    s1.name = "Amit"; s1.marks = 85;
    s1.show();             // Amit : 85
}
2. Classes & Objects: Access Specifiers, this, static, const
ENGLISH
  • Access specifiers: private (only inside the class; default for class), protected (class + derived classes), public (everywhere).
  • struct vs class: only difference is the default access: struct = public, class = private.
  • this pointer: hidden pointer to the current object; used to separate member and parameter names or return *this for chaining.
  • static member: belongs to the class, one copy shared by all objects (a counter). A static function can only use static members and has no this.
  • const member function (void f() const) promises not to change the object. mutable member can change even then.
  • Inline function: compiler may paste the body at call site (faster for tiny functions). Functions defined inside the class are implicitly inline.
HINGLISH
  • Access specifiers: private (sirf class ke andar; class me default), protected (class + derived classes), public (kahin bhi).
  • struct vs class: sirf default access ka fark: struct = public, class = private.
  • this pointer: current object ka hidden pointer; member aur parameter ka naam alag karne ya *this return karke chaining ke liye.
  • static member: class ka hota hai, saare objects ke liye ek hi copy (counter). Static function sirf static members use kar sakta hai aur uska this nahi hota.
  • const member function (void f() const) object ko badalne ka promise nahi todta. mutable member tab bhi badal sakta hai.
  • Inline function: compiler body ko call ki jagah paste kar sakta hai (chhote functions ke liye fast). Class ke andar define function by default inline hota hai.
class Counter {
    static int count;          // shared by all objects
    int id;
public:
    Counter() { id = ++count; }
    int getId() const { return id; }          // const function
    static int total() { return count; }      // static function
    Counter& setId(int id) { this->id = id; return *this; }  // this + chaining
};
int Counter::count = 0;        // definition outside the class
// Counter a, b;  Counter::total() -> 2
3. Constructors, Destructors & Rule of 3/5
ENGLISH
A constructor runs automatically when an object is created (same name as the class, no return type). A destructor (~Class()) runs when the object is destroyed, to release resources.
  • Types: default (no arguments), parameterized, copy Class(const Class& o), move Class(Class&& o) (C++11, steals resources from a temporary).
  • Initializer list Class(int a) : x(a) {} is the right way to init const members, references and base classes (and is faster).
  • Order: constructors run base → derived; destructors run derived → base. Members are built in the order they are declared.
  • Shallow vs deep copy: default copy copies pointer values (two objects point to the same memory, double delete!). Deep copy allocates new memory and copies the data.
  • Rule of 3: if you need a custom destructor, copy constructor or copy assignment, you probably need all three. Rule of 5 adds move constructor and move assignment. Rule of 0: prefer classes that need none (use smart pointers/STL).
  • Constructors cannot be virtual; explicit stops accidental implicit conversion; = default / = delete control generated functions.
HINGLISH
Constructor object banne par apne aap chalta hai (class ke naam jaisa, return type nahi). Destructor (~Class()) object khatam hone par chalta hai, resources chhodne ke liye.
  • Types: default (arguments nahi), parameterized, copy Class(const Class& o), move Class(Class&& o) (C++11, temporary se resources chura leta hai).
  • Initializer list Class(int a) : x(a) {} const members, references aur base classes ko init karne ka sahi tareeka hai (aur fast bhi).
  • Order: constructors base → derived; destructors derived → base. Members declare hone ke order me ban-te hain.
  • Shallow vs deep copy: default copy pointer ki value copy karta hai (do objects same memory par, double delete!). Deep copy nayi memory leta hai aur data copy karta hai.
  • Rule of 3: custom destructor, copy constructor ya copy assignment chahiye to teeno likho. Rule of 5 me move constructor aur move assignment bhi. Rule of 0: aisi classes banao jinhe kuch na likhna pade (smart pointers/STL).
  • Constructor virtual nahi ho sakta; explicit accidental implicit conversion rokta hai; = default / = delete auto-generated functions control karte hain.
class Buffer {
    int* data; int n;
public:
    Buffer(int n) : n(n), data(new int[n]) {}            // initializer list
    Buffer(const Buffer& o) : n(o.n), data(new int[o.n]) { // deep copy
        for (int i = 0; i < n; i++) data[i] = o.data[i];
    }
    Buffer& operator=(const Buffer& o) {                  // copy assignment
        if (this != &o) { delete[] data; n = o.n; data = new int[n];
            for (int i = 0; i < n; i++) data[i] = o.data[i]; }
        return *this;
    }
    ~Buffer() { delete[] data; }                          // destructor
};
4. Encapsulation, Abstraction & Friend
ENGLISH
  • Encapsulation in C++: make data private and give controlled access through getters/setters (so you can validate, e.g. no negative balance).
  • Abstraction is achieved with classes (hide implementation), header files, and abstract classes/interfaces (pure virtual functions). Difference: encapsulation = how you hide (data hiding); abstraction = what you expose.
  • Friend function/class: a non-member function or class allowed to touch private members. It is not inherited and not mutual. Use sparingly (it weakens encapsulation); common for operator<<.
  • Nested class lives inside another class; namespaces avoid name clashes.
HINGLISH
  • C++ me Encapsulation: data private rakho aur getters/setters se controlled access do (validation ke liye, jaise balance negative na ho).
  • Abstraction classes (implementation chhupana), header files aur abstract classes/interfaces (pure virtual functions) se milti hai. Fark: encapsulation = kaise chhupate hain (data hiding); abstraction = kya dikhate hain.
  • Friend function/class: non-member function ya class jise private members chhune ki permission hai. Inherit nahi hota aur mutual nahi hota. Kam use karo (encapsulation kamzor hota hai); operator<< ke liye common.
  • Nested class doosri class ke andar hoti hai; namespaces naam ki takkar rokte hain.
class Account {
    double balance = 0;                       // private data
public:
    void deposit(double x) { if (x > 0) balance += x; }   // validation
    double getBalance() const { return balance; }
    friend void audit(const Account& a);      // friend can see balance
};
void audit(const Account& a) { cout << a.balance; }
5. Inheritance: Types, Access Modes & Diamond Problem
ENGLISH
Inheritance lets a derived class reuse a base class (“is-a” relationship): class Dog : public Animal.
  • Types: single, multilevel (A→B→C), multiple (C : A, B), hierarchical (many from one base), hybrid.
  • Access modes: with public inheritance base public stays public, protected stays protected; with protected both become protected; with private both become private. Private members of the base are never accessible in the derived class (they exist but are hidden).
  • Constructor order: base first, then derived; destructor reverse. Pass base arguments through the initializer list: Derived(int a) : Base(a).
  • Diamond problem: D inherits B and C, which both inherit A, so D has two copies of A (ambiguity). Fix: virtual inheritance class B : virtual public A.
  • Composition (“has-a”) is often better than inheritance. Name hiding: a derived function with the same name hides all base overloads.
HINGLISH
Inheritance me derived class base class ko reuse karti hai (“is-a” relation): class Dog : public Animal.
  • Types: single, multilevel (A→B→C), multiple (C : A, B), hierarchical (ek base se kai), hybrid.
  • Access modes: public inheritance me base ka public public, protected protected rehta hai; protected me dono protected; private me dono private. Base ke private members derived me kabhi accessible nahi (hote hain par chhupe).
  • Constructor order: pehle base, phir derived; destructor ulta. Base ke arguments initializer list se: Derived(int a) : Base(a).
  • Diamond problem: D, B aur C se inherit karta hai jo dono A se; D me A ki do copies (ambiguity). Fix: virtual inheritance class B : virtual public A.
  • Composition (“has-a”) aksar inheritance se behtar hai. Name hiding: derived me same naam ka function base ke saare overloads chhupa deta hai.
class Animal {
public:
    Animal()  { cout << "Animal born\n"; }
    void eat() { cout << "eating\n"; }
};
class Dog : public Animal {
public:
    Dog()  { cout << "Dog born\n"; }
    void bark() { cout << "woof\n"; }
};
// Dog d;  prints: Animal born, Dog born   (base first)
// d.eat(); d.bark();
6. Polymorphism: Compile-time vs Run-time
ENGLISH
Polymorphism = one interface, many behaviours.
  • Compile-time (static) polymorphism: decided by the compiler. Function overloading (same name, different parameters), operator overloading, templates.
  • Run-time (dynamic) polymorphism: decided while running. Function overriding with virtual: a base pointer/reference calls the derived version. Needs the same signature.
  • How virtual works: each class with virtual functions has a vtable (table of function pointers); each object has a hidden vptr pointing to it. At call time the right function is looked up (late/dynamic binding). Cost: a little memory + one indirection.
  • override keyword catches signature mistakes; final stops further overriding. Overloading vs overriding: overloading = same class/scope, different parameters, compile-time; overriding = base vs derived, same signature, run-time.
  • Object slicing: assigning a derived object to a base object (not pointer/reference) cuts off the derived part and loses polymorphism.
HINGLISH
Polymorphism = ek interface, kai behaviours.
  • Compile-time (static) polymorphism: compiler decide karta hai. Function overloading (same naam, alag parameters), operator overloading, templates.
  • Run-time (dynamic) polymorphism: chalte waqt decide hota hai. virtual ke saath function overriding: base pointer/reference derived wala version call karta hai. Signature same hona chahiye.
  • Virtual kaise kaam karta hai: virtual functions wali har class ki ek vtable (function pointers ki table) hoti hai; har object me chhupa vptr usse point karta hai. Call ke time sahi function dhoondha jata hai (late/dynamic binding). Cost: thodi memory + ek indirection.
  • override keyword signature ki galti pakadta hai; final aage overriding rokta hai. Overloading vs overriding: overloading = same class/scope, alag parameters, compile-time; overriding = base vs derived, same signature, run-time.
  • Object slicing: derived object ko base object (pointer/reference nahi) me assign karne par derived hissa kat jata hai aur polymorphism khatam.
class Shape {
public:
    virtual void draw() { cout << "Shape\n"; }
    virtual ~Shape() {}                      // virtual destructor
};
class Circle : public Shape {
public:
    void draw() override { cout << "Circle\n"; }
};
Shape* p = new Circle();
p->draw();      // Circle  (run-time binding because of virtual)
delete p;       // safe: virtual destructor

// compile-time: overloading
int add(int a, int b)       { return a + b; }
double add(double a, double b) { return a + b; }
7. Abstract Classes, Interfaces & Virtual Destructor
ENGLISH
  • Pure virtual function: virtual void f() = 0; has no body in the base. A class with at least one is an abstract class: you cannot create objects of it, but you can have pointers/references to it. Derived classes must override it or they stay abstract too.
  • Interface in C++ = an abstract class with only pure virtual functions (no data).
  • Virtual destructor: if you delete a derived object through a base pointer and the base destructor is not virtual, only the base part is destroyed (undefined behaviour, leaks). Make the destructor virtual in every polymorphic base class.
  • Constructors cannot be virtual (the vptr is not set up yet). An abstract class can still have constructors, data, and normal functions.
HINGLISH
  • Pure virtual function: virtual void f() = 0; base me body nahi. Jis class me kam se kam ek ho wo abstract class hai: uska object nahi ban sakta, par pointer/reference ban sakta hai. Derived class ko use override karna padta hai warna wo bhi abstract rehti hai.
  • C++ me Interface = sirf pure virtual functions wali abstract class (data nahi).
  • Virtual destructor: base pointer se derived object delete karo aur base destructor virtual na ho to sirf base hissa destroy hota hai (undefined behaviour, leaks). Har polymorphic base class me destructor virtual rakho.
  • Constructor virtual nahi ho sakta (vptr abhi set nahi hota). Abstract class me constructors, data aur normal functions ho sakte hain.
class Payment {                         // interface
public:
    virtual void pay(double amt) = 0;   // pure virtual
    virtual ~Payment() = default;
};
class UPI : public Payment {
public:
    void pay(double amt) override { cout << "UPI paid " << amt; }
};
// Payment p;            // ERROR: abstract
// Payment* p = new UPI; // OK
8. Operator Overloading & Function Overloading Rules
ENGLISH
  • Function overloading: same name, different number or types of parameters (return type alone is not enough). Resolved at compile time.
  • Operator overloading: give operators meaning for your class (+ - == << [] ++). Written as a member operator+ or a friend function.
  • Cannot overload: :: (scope), . (member access), .*, ?:, sizeof. Cannot create new operators or change precedence/arity.
  • Binary operator as member takes 1 argument (the left side is *this); as non-member takes 2. Stream operators << and >> must be non-member (often friend). ++: prefix operator++(), postfix operator++(int) (dummy int).
  • Default arguments (void f(int a, int b = 5)) must be at the right end.
HINGLISH
  • Function overloading: same naam, parameters ki ginti ya type alag (sirf return type alag hona kaafi nahi). Compile time par resolve hota hai.
  • Operator overloading: operators ko apni class ke liye matlab dena (+ - == << [] ++). Member operator+ ya friend function ki tarah likhte hain.
  • Overload nahi ho sakte: :: (scope), . (member access), .*, ?:, sizeof. Naye operators nahi bana sakte aur precedence/arity nahi badal sakte.
  • Binary operator member ho to 1 argument leta hai (left side *this); non-member ho to 2. Stream operators << aur >> non-member (aksar friend) hone chahiye. ++: prefix operator++(), postfix operator++(int) (dummy int).
  • Default arguments (void f(int a, int b = 5)) hamesha right end se.
class Complex {
    double re, im;
public:
    Complex(double r = 0, double i = 0) : re(r), im(i) {}
    Complex operator+(const Complex& o) const { return Complex(re + o.re, im + o.im); }
    friend ostream& operator<<(ostream& os, const Complex& c) {
        return os << c.re << " + " << c.im << "i";
    }
};
// Complex a(1,2), b(3,4);  cout << a + b;   // 4 + 6i
9. Memory: Pointers, References, new/delete & Smart Pointers
ENGLISH
  • Pointer stores an address; can be null, reassigned. Reference is an alias for an existing variable; must be initialised, cannot be null, cannot be re-bound.
  • Stack vs heap: stack = automatic, fast, freed at scope end; heap = manual with new/delete (new[] pairs with delete[]). malloc/free (C) do not call constructors; new/delete do.
  • Problems: memory leak (forgot delete), dangling pointer (points to freed memory), double delete, null dereference.
  • RAII (Resource Acquisition Is Initialization): acquire in the constructor, release in the destructor, so cleanup is automatic.
  • Smart pointers (<memory>): unique_ptr (sole owner, cannot copy, can move), shared_ptr (shared ownership by reference counting), weak_ptr (non-owning, breaks cycles). Prefer make_unique/make_shared.
  • Copy vs move: move transfers resources from a temporary (std::move) instead of copying (faster). lvalue has a name/address; rvalue is a temporary.
HINGLISH
  • Pointer address store karta hai; null ho sakta hai, dobara assign ho sakta hai. Reference existing variable ka alias hai; init karna zaroori, null nahi ho sakta, re-bind nahi hota.
  • Stack vs heap: stack = automatic, fast, scope khatam hone par free; heap = manual new/delete se (new[] ka jodi delete[]). malloc/free (C) constructors call nahi karte; new/delete karte hain.
  • Problems: memory leak (delete bhool gaye), dangling pointer (free hui memory ko point), double delete, null dereference.
  • RAII: constructor me resource lo, destructor me chhodo, to cleanup apne aap hota hai.
  • Smart pointers (<memory>): unique_ptr (akela owner, copy nahi, move ho sakta hai), shared_ptr (reference counting se shared ownership), weak_ptr (owner nahi, cycles todta hai). make_unique/make_shared ko prefer karo.
  • Copy vs move: move temporary se resources transfer karta hai (std::move) copy ki jagah (fast). lvalue ka naam/address hota hai; rvalue temporary hota hai.
#include <memory>
void demo() {
    int x = 10;
    int* p = &x;      // pointer
    int& r = x;       // reference (alias)
    r = 20;           // x is now 20

    auto u = make_unique<int>(5);      // freed automatically
    auto s1 = make_shared<int>(7);
    auto s2 = s1;                      // ref count = 2
}   // no leaks, no delete needed
10. Templates & STL (Generic Programming)
ENGLISH
  • Templates let you write code once for any type (compile-time polymorphism). Function template: template<typename T> T maxOf(T a, T b). Class template: template<class T> class Stack. Specialization gives a special version for one type.
  • STL (Standard Template Library) has 3 parts: containers, iterators, algorithms (+ function objects/lambdas).
  • Containers: vector (dynamic array, O(1) push_back amortised), list (doubly linked), deque, stack, queue, priority_queue, set/map (ordered, red-black tree, O(log n)), unordered_set/unordered_map (hash, O(1) average).
  • Algorithms: sort, find, reverse, binary_search, accumulate. Lambda: [&](int a){ return a*2; }.
HINGLISH
  • Templates se code ek baar likho aur kisi bhi type ke liye chalao (compile-time polymorphism). Function template: template<typename T> T maxOf(T a, T b). Class template: template<class T> class Stack. Specialization kisi ek type ke liye alag version deti hai.
  • STL (Standard Template Library) ke 3 parts: containers, iterators, algorithms (+ function objects/lambdas).
  • Containers: vector (dynamic array, push_back amortised O(1)), list (doubly linked), deque, stack, queue, priority_queue, set/map (ordered, red-black tree, O(log n)), unordered_set/unordered_map (hash, average O(1)).
  • Algorithms: sort, find, reverse, binary_search, accumulate. Lambda: [&](int a){ return a*2; }.
template <typename T>
T maxOf(T a, T b) { return (a > b) ? a : b; }
// maxOf(3, 7) -> 7     maxOf(2.5, 1.5) -> 2.5

#include <vector>
#include <algorithm>
vector<int> v = {5, 2, 9, 1};
sort(v.begin(), v.end());                       // 1 2 5 9
sort(v.begin(), v.end(), [](int a, int b){ return a > b; });  // descending
11. Exception Handling
ENGLISH
Exceptions separate error handling from normal code. Keywords: try (risky code), throw (raise an error), catch (handle it).
  • Catch the most specific type first, general catch(...) last. Catch by const reference (catch(const exception& e)) to avoid slicing.
  • Stack unwinding: when thrown, the stack is unwound and destructors of local objects run (so RAII keeps things safe).
  • Standard exceptions in <stdexcept>: runtime_error, out_of_range, invalid_argument, bad_alloc. Make your own by inheriting from std::exception.
  • noexcept promises a function will not throw. Never throw from a destructor. Uncaught exceptions call terminate().
HINGLISH
Exceptions error handling ko normal code se alag karte hain. Keywords: try (risky code), throw (error uthana), catch (handle karna).
  • Sabse specific type pehle catch karo, general catch(...) aakhir me. const reference se catch karo (catch(const exception& e)) taaki slicing na ho.
  • Stack unwinding: throw hone par stack unwind hota hai aur local objects ke destructors chalte hain (isliye RAII safe rakhta hai).
  • Standard exceptions <stdexcept> me: runtime_error, out_of_range, invalid_argument, bad_alloc. Apni exception std::exception se inherit karke banao.
  • noexcept promise karta hai ki function throw nahi karega. Destructor se kabhi throw mat karo. Uncaught exception terminate() call karti hai.
double divide(int a, int b) {
    if (b == 0) throw runtime_error("Divide by zero");
    return (double)a / b;
}
int main() {
    try {
        cout << divide(10, 0);
    } catch (const runtime_error& e) {
        cout << "Error: " << e.what();     // Error: Divide by zero
    } catch (...) {
        cout << "Unknown error";
    }
}
12. Useful Keywords & Concepts (static, const, explicit, virtual…)
ENGLISH
  • const: value cannot change; const int* p (data const), int* const p (pointer const), const member function.
  • static: in a function = keeps value between calls; in a class = shared by all objects; at file level = visible only in that file.
  • explicit blocks implicit conversions via single-argument constructors. mutable allows change inside a const function. volatile stops compiler optimising a variable. auto deduces type. nullptr is the type-safe null.
  • Shallow vs deep copy, stack vs heap, copy vs move (covered above). Namespace: std::; avoid using namespace std; in headers.
  • Interview facts: size of an empty class = 1 byte (objects need unique addresses); a class with a virtual function adds a vptr (8 bytes on 64-bit); sizeof includes padding.
HINGLISH
  • const: value badal nahi sakti; const int* p (data const), int* const p (pointer const), const member function.
  • static: function me = calls ke beech value yaad rakhta hai; class me = saare objects me shared; file level par = sirf us file me visible.
  • explicit single-argument constructors se implicit conversion rokta hai. mutable const function ke andar bhi change allow karta hai. volatile compiler ko variable optimise karne se rokta hai. auto type khud nikalta hai. nullptr type-safe null hai.
  • Shallow vs deep copy, stack vs heap, copy vs move (upar cover). Namespace: std::; headers me using namespace std; avoid karo.
  • Interview facts: khali class ka size = 1 byte (objects ka unique address chahiye); virtual function wali class me vptr jodta hai (64-bit par 8 bytes); sizeof me padding bhi aati hai.
13. SOLID Principles & Basic Design Patterns
ENGLISH
  • S – Single Responsibility: a class should have one reason to change.
  • O – Open/Closed: open for extension (add new classes), closed for modification (do not edit working code).
  • L – Liskov Substitution: a derived object must work wherever the base is expected.
  • I – Interface Segregation: many small interfaces beat one fat interface.
  • D – Dependency Inversion: depend on abstractions (abstract classes), not concrete classes.
Common patterns: Singleton (one instance only), Factory (create objects without exposing the class), Observer (notify many on change), Strategy (swap algorithms at run time).
HINGLISH
  • S – Single Responsibility: class ke badalne ki ek hi wajah honi chahiye.
  • O – Open/Closed: extension ke liye open (nayi classes jodo), modification ke liye closed (chalte code ko mat chhedo).
  • L – Liskov Substitution: jahan base chahiye wahan derived object bhi sahi chale.
  • I – Interface Segregation: ek moti interface se kai chhoti interfaces behtar.
  • D – Dependency Inversion: abstractions (abstract classes) par depend karo, concrete classes par nahi.
Common patterns: Singleton (sirf ek instance), Factory (class dikhaye bina object banana), Observer (change par kai ko notify), Strategy (run time par algorithm badalna).
class Logger {                          // Singleton
    Logger() {}                         // private constructor
public:
    Logger(const Logger&) = delete;
    static Logger& get() { static Logger inst; return inst; }  // thread-safe in C++11
    void log(const string& m) { cout << m << "\n"; }
};
// Logger::get().log("hello");
